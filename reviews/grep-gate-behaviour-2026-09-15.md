# Grep ゲートの実機挙動と TP 修正群の効果（2026-09-15、実測 $2.853）

`compare-edit-dense-lines` 1ケースを2つの固定チェックアウトで各4回走らせた記録。
問いは「TP2 → TP1 → TP4 → TP5 → TP9 の修正に、比較評価で見える効果があるか」。

**答え：無い。** TP5 だけが挙動を変えうる修正だが差は検出できず、
TP2 / TP1 はこのケースでは効果が出る余地が無く、TP4 / TP9 は実行時の挙動を変えない。
副産物として、**ゲート自体が7/7で機能している**ことと、
**親は規則を知っていても最初の呼び出しを上限なしで出す**ことが観測できた。

## 1. 実行条件

| 項目 | 値 |
|---|---|
| ケース | `compare-edit-dense-lines`（`auto` 単独モード）、対象 `dense_edit.txt` 80,032 B |
| 腕A | scratchpad の detached worktree、**`16ff26e` 固定**（TP 修正前） |
| 腕B | 同、**`83a3602` 固定**（TP2/TP1/TP4/TP5/TP9 適用後） |
| 回数 | 各4回、**交互**に実行（環境ドリフトを片方に寄せないため） |
| 事前確認 | 両チェックアウトで `git status` は生成物（`.pyc`）のみ、`judge.py --selftest` 通過 |
| 設定 | `SENDBACK=on`（A スイート再走と同条件） |
| 実測費用 | **$2.853**（腕A $1.454、腕B $1.399） |

腕Aには A スイート再走（`16ff26e`）で得た同ケースの1実行（`ZH05`）も同じ条件なので、
挙動の集計では5実行として扱う。費用は8実行ぶんである。

## 3. 効果の判定

### 3.1 TP5（SKILL.md の「is not hooked」訂正）→ 検出できない

拒否ゼロの割合は 2/5 対 0/4 で、**向きはむしろ逆**。
Fisher 正確検定で p≈0.44、この標本数では偶然と区別できない。
「フックされると書けば親が先回りして `head_limit` を付ける」という効果は観測されなかった。

差が無いこと自体を主張するにも標本が足りない。言えるのは
**8実行程度では検出できない大きさである**ということだけである。

### 3.2 TP2（cwd 解決）・TP1（writer の誘導先）→ 効果が出る余地が無い

A スイート全実行のトランスクリプトを数えると、
Grep のパスは**9件すべて絶対パス**、`code-writer` からの Grep は**0件**、
相対オペランドの `wc`/`stat` も**0件**（1件あった `stat -c '%s %n'` は書式文字列で、
`_TAKES_VALUE` が既に正しく扱っている）。

比較評価の fixture は絶対パスで生成され、フックの cwd とセッション cwd が一致する。
TP2 が直したのは両者が食い違ったときの挙動なので、**評価はその条件を作らない**。
実利用ではプロジェクトルートを cwd にした相対パスが普通なので、
**この欠陥は評価では永久に見えず、実利用でだけ出る**。回帰テストで固定した理由がこれである。

### 3.3 TP4（README）・TP9（docstring）→ 測る対象ではない

読み手は人間で、モデルはどちらも読まない。

## 4. 副産物（こちらのほうが価値がある）

### 4.1 ゲートは取りこぼしていない

予算超過ファイルへの**上限なし content Grep は9実行中7回発生し、7回とも拒否された**。
拒否の内訳は未計測5、上限2。すべて**1往復で回復**し、
拒否上限（`DENY_CAP = 6`）に達した実行は0件。
`files_with_matches` と計測済み `head_limit` は一度も誤って拒否していない。

`reviews/grep-hook-implementation-2026-09-15.md` §5 が
「実機で拒否が起き、親が直して通ったという観測は0件」としていた点は、これで解消する。

### 4.2 往復費用は実行間のばらつきに埋もれる

設計調査 §1.5 は親ターン1回を約 $0.013 と見積もっていた。
腕A平均 $0.363 対 腕B平均 $0.350 で、**拒否1往復ぶんの差は実行間のばらつきより小さい**。
拒否0回の実行（$0.300、$0.372）と拒否1回の実行（$0.300〜$0.412）が重なっており、
この設計では往復費用を分離して測れない。見積り自体を否定も肯定もしない。

### 4.3 親は規則を知っていても最初の呼び出しを上限なしで出す

9実行中7回。腕Bでは4/4。SKILL.md に「フックされる」「`head_limit` 1-20」と
書いてあっても、最初の呼び出しはそれを満たさない。

これは `reviews/behaviour-measurement-2026-09-15.md` の
「文言を足しても4件中3件は行動が変わらない」という既存の実測と整合し、
**警告ではなく拒否にした設計判断**（`grep-hook-implementation-2026-09-15.md` §2.1）を
裏づける追加の証拠である。文言だけに頼っていれば、この7回はそのまま
80 KB のファイルへの無制限 content 検索になっていた。

## 5. 限界

- 1ケース・9実行である。他のケースや一般の利用に外挿できない。
- 腕Bは README 修正（`83a3602`）を含むが、README はモデルが読まないので
  TP5 の測定には影響しない。
- 拒否ゼロの実行が腕Aにだけ2件あったことを「修正が悪化させた」と読んではいけない。
  §3.1 のとおり区別がついていない。
- `DENY_CAP = 6` は今回も一度も到達しておらず、**依然として実測の根拠が無い**。
