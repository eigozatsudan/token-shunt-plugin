## 2. 用量反応にする（二値にしない）

「全読が要るか否か」の二値ではなく、**読ませる量を変えて傾きを見る。**

同じ形の問い（「このファイルで最後に定義されたメソッド名と行番号」）を、
**大きさの違う 4 ファイル**に当てる。**問いの種類は固定し、量だけ変える。**

| case | ファイル | bytes |
|---|---|---|
| `redmine-last-journal` | `app/models/journal.rb` | 12,803 |
| `redmine-last-user` | `app/models/user.rb` | 35,747 |
| `redmine-last-query` | `app/models/query.rb` | 54,439 |
| `redmine-last-helper` | `app/helpers/application_helper.rb` | 70,137 |

いずれも答えはファイルの **97% 以降**にあり、先頭だけ読んでも届かない。

### 2.1 用量は仮定せず実測する

前回、親は Grep や Bash を使い、**ファイルサイズは親が飲む量を決めなかった。**
したがって用量は**ファイルサイズではなく、実測した
`direct` の `parent_read_bytes`** とする。**親がどう振る舞っても成立する。**

## 4. 解析（走らせる前に固定する）

**主要: 48 対それぞれについて
（direct の `parent_read_bytes`）と（auto の費用 − direct の費用）の
Spearman 順位相関。** 予測は **負**（読まされるほど auto の不利が縮む）。

- **並べ替え検定**（両側、10,000 回、`random.Random(20260917)` で固定）。
  正規性も線形性も仮定しない。
- **対ごとに数える**。case ごとの中央値 4 点では、どう転んでも p < 0.05 に届かない
  （n = 4 の Spearman は両側で最小 0.083）。**点を 4 つに減らさない。**

**副次、すべて事前に決めたもの:**

1. case ごとの表: direct の `parent_read_bytes` 中央値、費用比、正答。
2. **`auto` の `parent_read_bytes` が全 48 run で 0 か**（前回の再現確認）。
3. 親が使った道具（Grep / Bash / Read）の内訳。
4. 主要と同じ相関を、**前回の 40 対を足した 88 対**でも計算する。
   **仮説を生んだデータを含むので、こちらは副次である。** 両方出す。
5. `accuracy_any` を両腕で。

**中間解析はしない。**

## 5. 止める条件（前回と同じものを再掲する）

- 費用が枠に達したとき（`spend.py` が止める）。
- 計器が定義どおり動いていないと分かったときに限り中止してよく、
  そのときは**何が定義と違ったかを数字で示す**。
- **結果の向きや大きさは、止める理由にならない。**

## 6. 予測を外したときにどう書くか（事前に決める）

- 相関が**出ない**なら、「**§1 の 2 点は偶然で説明できる**」と書く。
- 相関が**逆向き**なら、そう書く。**仮説を作り直して同じデータで検証しない。**
- どちらの場合も、**前回の結論（本文は親に入らない）は独立に成立する。**
  費用の話が崩れても、そちらは崩れない。

## 7. 事前に認めている弱点

- **問いの形は 1 つだけ**（末尾の定義を訊く）。
  「全読を強いる問い」一般ではない。
- 費用はモデル価格に依存する。**今日の値である。**
- 用量と費用差は**同じ run から来る**ので、独立ではない。
  相関は「この設定でそう動く」以上を意味しない。
