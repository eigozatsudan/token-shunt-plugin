# 宣言パス外 Read 拒否の実機確認・事前登録（2026-09-16）

`8f25a98`（`reviews/a-suite-failures-9346d19-2026-09-16.md` §14）の実機確認。
**本記録は走らせる前にコミットする。** 項目・N・判定基準を先に固定する。

## 1. 問い

新しい PreToolUse deny は**委譲するすべての run に効く**。塞ぎたいのは
「前起動のパスの再読」だが、起動プロンプトの解析に失敗すれば
**正規の Read を拒否する**（§14.3 に記録した偽拒否リスク）。

測るのは「通常の委譲 run で偽拒否が起きていないか」である。
効果（再読が止まるか）は §4 が 1 run の観測なので、ここでは測らない。

## 2. 条件

腕は 1 本（`8f25a98`）。枠は `d985e51` の混在パス測定と**同一**にする:

- `compare-explicit-multifile/haiku`
- `compare-explicit-multifile/sonnet`
- `auto-explicit-multifile/haiku`

**2 周 × 3 枠 = 6 run。** `SENDBACK` は既定 off。
比較対象は `reviews/mixed-path-report-2026-09-16.md`（`d985e51`、同一枠・同一 N、
$0.791、報告 6/6 絶対パス、2 周目は isolation 以外 3 枠とも pass）。
`d985e51` と `8f25a98` の差は本変更と記録のみである。

## 3. 事前登録する項目

計器は run の transcript にある hook イベント（`hook_name` と deny の
`permissionDecisionReason`）と `evals/compare/retention_probe.py`。
deny は transcript に載ることを既存 run で確認済み。

| # | 項目 | 定義 |
|---|---|---|
| N1 | スコープ拒否 | 理由に `Read only the paths this invocation was given` を含む deny の件数 |
| N2 | 他の token-shunt deny | 上記以外の deny の件数（内訳を記録） |
| N3 | verdict | 枠ごとの pass / fail（`d985e51` の 2 周目と比較） |
| N4 | 報告の形 | `report_shape()`（絶対 / 混在 / 全相対 / 判定不能） |
| N5 | 計器の生存 | run 中に作られた reader state に `scope` が**非空**で入った起動の数 |
| N6 | 費用 | run ごとの `total_cost_usd` |

N5 を必ず取る。N1 = 0 は「偽拒否が無い」とも「スコープが常に空で検査が
死んでいる」とも読めるので、**スコープが実際に解決されたことを示せないなら
N1 = 0 は何の証拠にもならない**（E2b で同じ誤りをした）。

## 4. 判定基準（事前）

1. **N5 ≥ 1 かつ N1 = 0 なら、偽拒否は観測されなかったと結論する。**
   3 の法則で上限のみ記録する（起動を分母に取る）。
2. **N1 ≥ 1 なら 1 件ずつ中身を見る。** 拒否されたパスが起動プロンプトに
   書かれていたなら**偽拒否**であり、解析の欠陥として直す。
   前起動のパスなら真の阻止として記録する。どちらかを結果が出てから
   決め直さない。
3. **N5 = 0 なら、検査が働いていないという結果として記録する。**
   その場合 N1 = 0 を「安全」と書かない。
4. N3 が `d985e51` の 2 周目より悪化していれば、悪化した枠の transcript を
   deny の有無まで遡って記録する。偽拒否が verdict に出る唯一の経路である。
