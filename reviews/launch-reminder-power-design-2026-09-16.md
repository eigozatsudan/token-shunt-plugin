## 4. 事前登録する項目

計器は `evals/compare/retention_probe.py`（`score_dir` の枠ごとの値）。

| # | 項目 | 定義 |
|---|---|---|
| P1 | 短縮 | ワーカーの実在絶対パス付き `confirmed:` 行が親の最終回答で短縮・欠落した run 数 |
| P2 | 測定可能 | 判定の分母（ワーカーが実在絶対パス付きの行を返した run 数） |
| P3 | 配送 | リマインダが親の文脈に入った run 数（treatment のみ。`reminder_delivered`） |
| P4 | verdict | 枠の pass / fail（isolation 除く） |
| P5 | 費用 | run ごとの最終 `total_cost_usd` の和（起動プローブ込み） |

P5 は**各 run の最終値を 1 回だけ**数える（`reader-scope-live` §2.1 の訂正と同じ数え方）。

## 5. 判定基準（事前）

分母は P2。

1. **Fisher 両側 p < 0.05 なら効果ありと書く。** 方向も併記する。
2. **p ≥ 0.05 なら「18 対 18 でも有意差なし」と書く。** 効果なしとは書かない
   （この N で否定できるのは大きい効果だけである）。信頼区間の代わりに
   両腕の率と差を記録する。
3. **中間の打ち切り（1 回だけ、9 対 9 の時点）**: control の短縮が **2/9 以下**なら、
   基準率が前提（1/3）より低いので**そこで止める**。残りは払わない。
   結果は「基準率が低すぎて、この予算では判定できない」と記録する。
   これ以外の中間解析はしない（p 値を覗いて止めることはしない）。
4. P2 が 1 腕 15 未満なら、その腕は判定に使わない。枠がワーカーを起動して
   いないということなので、枠選びの失敗として記録する。
5. P3 が treatment で 18/18 でないなら、配送されなかった run を明記し、
   **配送された run だけの副次解析も併記する**（主解析は割り付けどおり全 run）。

## 6. 費用

実測 $0.127/run（この枠）＋ 起動プローブ $0.051/起動。1 腕 18 起動で約 $3.2、
**合計約 $6.4。上限 $8。** 累積が上限を超えたらその時点で止め、
そこまでの N で §5 の基準を当てる（N が減れば当然 p は出にくい。それも結果である）。
