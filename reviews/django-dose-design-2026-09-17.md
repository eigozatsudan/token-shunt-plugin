# 用量と費用の関係が別の corpus でも成り立つかの検証・事前登録（2026-09-17）

`reviews/redmine-dose-2026-09-17.md` の追試。**走らせる前に本記録をコミットする。**

## 1. 何を確かめるのか

dose 測定は**本リポジトリで最も強い結果**である（ρ = −0.879、p < 1e-4）。
弱いのは**結論そのものではなく、その一般性**である:

| 既に言えること | 弱いところ |
|---|---|
| 親が飲まされる量が増えるほど auto の相対的な費用は下がる | **corpus は Redmine ひとつ、言語は Ruby ひとつ** |
| 比が 1 を跨ぐのは **2〜3 万バイト付近** | **4 点だけで引いた跨ぎ点** |

**本測定は跨ぎ点に金を使う。** 弱いのはそこだからである。

## 2. 測る問い

**Redmine で見た用量と費用の関係は、別の corpus・別の言語でも成り立つか。
そして跨ぎ点は同じあたりに来るか。**

## 3. 設計

- **corpus は Django 5.2.1、コミット `bc833e8883db4a333a6485d91637b78c85e2b13b`**
  （`DJANGO_ROOT` で渡す。`external_root` は run.sh が変数名として汎用に扱う）。
- **8 ファイル、サイズが 8 KB〜119 KB に広がるもの**（§3.1）。
  **4 点だった跨ぎ点を 8 点にするのが本測定の主目的である。**
- **各 case 10 対（direct と auto）、合計 80 対 160 run。結果を見て伸ばさない。**
- **問いの形は Redmine と同じ**「最後に定義されている関数の名前と def 行の行番号」。
  **同じ問いで corpus だけ替える**ので、差が出たらそれは corpus/言語の差である。

### 3.2 用量はファイルサイズではない（前回の教訓）

**サイズ順と用量順は一致しない。** Redmine では `query.rb` が最大級なのに
親が飲んだ量は最小だった（親が Bash で全読を避けたため）。
**用量は `direct` 腕の実測 `parent_read_bytes` で測る。**
**上の表のサイズは並べるためのものであって、解析には使わない。**

## 4. N と枠

**総枠 $150（指定を受けた）。累計 約 $95.3。残り約 $54.7。**
**本段階の上限 $40**、見込み **$30**。

1 run の見積り: Redmine の dose ブロックは 96 run で $13.11（$0.137/run）。
Django のほうが大きいファイルを含むので **$0.19/run** と見る（160 run で $30.4）。
**reserve は $0.70** — 直近ブロックの最も高い 1 run $0.6721 から
（メモリ `billable-stop-rule-needs-a-mechanism`、平均ではなく最大）。
**run ごとに `spend.py --cap 40 --reserve 0.70` を通し、exit 3 で抜ける。**

**枠に達したら、達したところまでで報告する。後から足さない。**
case の巡回順で回すので、**どの case も同じだけ欠ける。**

## 5. 解析（走らせる前に固定する）

**主要: 80 対の（`direct` の実測 `parent_read_bytes`）×（auto の費用 − direct の費用）
の Spearman ρ。並べ替え検定（両側・10,000 回・`random.Random(20260917)`）。**

**予測: ρ < 0、p < 0.05。** Redmine は −0.879 だった。

**副次、すべて事前に決めたもの:**

1. **case ごとの中央値の表**（実測用量、direct $、auto $、比）と**跨ぎ点**。
2. **内訳**: ρ(direct $ × 用量) と ρ(auto $ × 用量)。
   Redmine では **+0.921 と +0.151** で、
   **関係は「auto が安い」ではなく「direct が高い」から出ていた。**
   **方向を取り違えないために必ず出す。**
3. **auto 腕の `parent_read_bytes` が 0 でない run の数と、その中身の分類**
   （フックの拒否文か、corpus の本文か）。Redmine は本文としては 88/88 で 0。
4. `accuracy_any` を両腕で。
5. **`child_no_body` の失敗件数と理由**（フェンスを含む）。**記録するだけで検定しない。**
6. case ごとの実費。

**中間解析はしない。** 採点は `pairs.py` が出す行に対して行う
（`cf88864` / `785e7c6` で片腕と正答列を直した。**本測定は両腕なので元から使える**）。

## 6. 予測を外したときにどう書くか（事前に決める）

- **ρ < 0 で p < 0.05** なら、「**Redmine の関係は別の corpus・別の言語でも再現した**」。
- **そうでない**なら、「**再現しなかった**」と書き、
  **Redmine の結果は corpus に固有である可能性がある**と明記する。
  **その場合に Redmine の記録を書き換えない。** 並べて残す。
- **跨ぎ点が 15〜40 KB に入る**なら「**跨ぎ点も再現した**」。
  **外れる**なら「**関係は再現したが跨ぎ点は corpus に依る**」。
  **観測範囲内で比が 1 を跨がない**なら**そのまま報告し、外挿しない。**

**この 15〜40 KB という帯は今ここで決めている。後から動かさない。**

## 7. 打ち切り

- 費用が枠に達したとき（`spend.py` が止める）。
- 計器が定義どおり動いていないと分かったときに限り中止してよく、
  そのときは**何が定義と違ったかを数字で示す**。
- **結果の向きや大きさは、止める理由にならない。**

## 8. 事前に認めている弱点

- **corpus 2 つは corpus の標本ではない。** 言語も 2 つで、
  **言語と corpus は分離できない。**
- **問いの形は 1 つ**（Redmine と同じにしたのは意図的だが、
  **問いの形への依存は本測定では分からない**）。
- **ファイルの選択は私が行った**（サイズが広がるように選んだ）。
  **用量の広がりは選択の結果であって、Django の代表値ではない。**
- 費用も挙動も**今日のモデル価格・今日のモデル**に依る。
- **eval の case であって、実際の利用の標本ではない。**
