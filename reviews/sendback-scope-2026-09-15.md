# 差し戻しの有効範囲・回復手順・追加費用（2026-09-15、課金なし）

検出基盤（`evals/compare/session_extract.py`、`evals/compare/retention_checks.py`）と
3件の記録（`final-answer-detection-2026-09-15.md`、`stop-hook-spec-2026-09-15.md`、
`session-extraction-2026-09-15.md`）を起点に、Stop／SubagentStop 差し戻しの
**適用できる範囲・回復の道筋・増える費用**を保存済みデータだけで見積もる。
フックの実装と課金測定は保留のままで、本稿でモデルは1回も起動していない。

## 1. 母集団と分類（セッション単位）

対象は bulk-reader の起動を含む実セッション **456件**。
分類は下の順で1件1クラスに割り当てる（スクリプト: scratchpad `sendback_scope.py`）。

| クラス | 条件 | 件数 |
|---|---|---|
| `OK` | 全 confirmed 行が逐語で残っている | 69 |
| `A-parent-lost` | 子が使える項目を出し、親が取りこぼした | **308** |
| `B-child-no-item` | 子が使える絶対パス付き項目を出していない | 68 |
| `U-child-output` | 子出力を取得できない（不一致・PARTIAL 等） | 8 |
| `U-files-gone` | 子の引用ファイルが現存せず判定できない | 3 |
| `U-no-final-text` | 最終回答を特定できない | 0 |
| 計 | | 456 |

`U-*` の11件は**判定不能**であり、親の欠落にも子の欠落にも数えない。

## 2. 差し戻しが効く範囲

### 2.1 上限は 308 件（親側の欠落のみ）

差し戻しで回復しうるのは `A-parent-lost` の308件だけである。

- `B-child-no-item` 68件は、親をもう一度走らせても復元する材料が無い。
  親の Stop ではなく **SubagentStop（子の結論直前）か再委譲**が対応先になる
  （`stop-hook-spec-2026-09-15.md` §3.1）。
- `U-*` 11件は差し戻しの対象外。取得不能・ファイル消失を親の欠落として
  差し戻すと、正しい回答を壊す側に回る。

### 2.2 308 は上限であって達成値ではない

保存データから確認できるのは「差し戻すべき状態を検出できる」ところまでで、
**差し戻した親が実際に回復するかは未測定**である。回復率は課金測定でしか出ない。

さらに上限側にも2つの目減り要因があり、いずれも保存済み transcript からは
件数を出せない。

| 要因 | 内容 | 保存データでの扱い |
|---|---|---|
| ブロック破棄 | CLI は tool result／MCP end-turn／loop tick で終わったターンの Stop ブロックを破棄する（`[end-turn] Stop hook block discarded …`） | 道具列だけでは終了原因を判別できない。件数**不明** |
| 再ブロック上限 | `stop_hook_active` が真の間は成功を返す規約。既定では実質**1ターン1回**（`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` で引き上げ可） | 1回の差し戻しで直らない場合の再試行は既定で不可 |

`no_final_text` は「最終回答を特定できなかった」状態であり、
破棄経路の終了原因と同一視しない。今回の456件では0件である。

### 2.3 入力はフック時点で揃うか

Stop フックの入力は親の `transcript_path` で、子の答えは
(a) セッション内の `<task-notification>` と (b) `subagents/agent-<id>.jsonl` の
両方から取れる。二つの数は別物なので分けて出す。

| 段階 | 件数 | 除外 |
|---|---|---|
| 子出力を取得できた | **448** | 取得不能 8 |
| さらに引用先の実在まで確認でき、判定できた | **445** | 上記に加えファイル消失 3 |

最終回答は456件すべてで特定できた。つまり差し戻し判断に必要な入力は、
追加の取得手段なしにフック時点で揃う。ただし取得できた448件のうち3件は、
引用ファイルが現存せず**取得はできたが判定はできない**。

## 3. 回復手順

### 3.1 何を差し戻し文に載せるか

| 損失の形 | 行数 | 回復指示 |
|---|---|---|
| `dropped`（行ごと消えた） | 840 | 該当行を逐語で再掲させる |
| `altered`（パスは残り本文が変わった） | 162 | 元の本文に戻させる |
| `demoted`（`unconfirmed:` へ降格） | 0 | 実コーパスでは発生せず（合成テストのみ） |
| `kept` | 15 | — |

308件中 **301件は保持行が1行も無い**。つまり典型的な失敗は
「一部を落とす」ではなく「`confirmed:` 行を丸ごと書かない」であり、
差し戻し文は**欠落行の全文**を載せる必要がある。

### 3.2 ファイル被覆では足りない

308件のうち、被覆検査でも見えるのは253件、**55件は被覆が成立したまま行が落ちている**
（同一ファイルの2件目以降の事実）。被覆だけを根拠に差し戻すと、この55件を見逃す。
製品契約は「全 confirmed 行の逐語転記」であり、被覆はその代替にならない。

### 3.3 手順の分岐

1. 子出力を取得 → 取れなければ**差し戻さない**（判定不能）。
2. `check_child_items` が VIOLATION → 親ではなく子の問題。SubagentStop か再委譲。
3. `check_line_retention` が VIOLATION → 欠落・改変行を全文添えて Stop で差し戻す。
4. 再ブロックは既定で1回。直らない場合は人手か再委譲に落とす。

## 4. 追加費用

### 4.1 単価の根拠

課金済み24実行の `result` イベントの `modelUsage`（`costBasis: "list"`）から
最小二乗で単価を復元した。

| モデル | out | cache read | cache write | 備考 |
|---|---|---|---|---|
| `claude-haiku-4-5` | $5.00 | $0.100 | $1.25 | n=33、入力 $1.00 も含め素直に復元 |
| `claude-sonnet-5` | $4.92 | $0.319 | $3.36 | n=34、入力は $3.00/Mtok に固定して当てはめ |

sonnet の `inputTokens` 列はほぼ退化しており（1実行あたり10前後）、
自由に当てはめると入力単価が負の値になる。よって入力だけ公称値に固定した。
残差の最大は $0.016（対象費用は $0.024–$0.190）。**推定値であり請求値ではない。**

### 4.2 1回の差し戻しの費用

実セッション398件の最終ターン usage から、文脈長は中央値 36,098 tok
（平均 40,232、p90 40,565、最大 271,204）。差し戻しは
「同じ文脈の再読み込み（cache read）＋差し戻し文（cache write）＋回答の作り直し（output）」。

| 断面 | 文脈 | 差し戻し文 | 作り直し | 1回あたり |
|---|---|---|---|---|
| 中央値 | 36,098 tok | 695 B | 1,195 B | **$0.0136** |
| 平均 | 40,232 tok | 733 B | 1,357 B | $0.0151 |
| p90 | 40,565 tok | 1,174 B | 2,368 B | $0.0168 |
| 最大 | 271,204 tok | 2,939 B | 6,820 B | $0.0974 |

### 4.3 規模あたり

| 単位 | 費用 |
|---|---|
| 該当308件に1回ずつ | 約 **$4.7** |
| 該当100件あたり | 約 $1.5 |
| 全セッション100件あたり（308/456 が該当） | 約 $1.0 |

比較として、今回の測定コーパスの1実行あたり実測平均は $0.163 だった。
差し戻し1回はその **1割弱**にあたる。

#### 精度の限界

これらは**復元単価による参考推定**である。§4.1 の当てはめの残差は最大 $0.016 で、
1回あたりの推定中央値 $0.0136 と同程度の大きさがある。つまり
1回分の金額は**桁の目安としてしか読めない**。件数をまとめた $4.7 や $1.5 も
同じ単価に乗っているため、精度は上がらない。

また「1回で回復する」前提を置いても、この推定誤差が残るため
**厳密な下限ではない**。再試行や回復失敗を含めればさらに増える方向に動く。

## 5. 判断

- 差し戻しの**有効範囲の上限は 456件中 308件**。残り68件は子側の問題で、
  親の Stop では回復しない。11件は判定不能。
- 破棄経路と1ターン1回の再ブロック上限により、308件のうちどれだけ実際に
  差し戻せるかは**保存データからは出せない**。
- 回復指示は**欠落行の全文**が要る。308件中301件は保持行がゼロで、
  被覆だけでは55件を取りこぼす。
- 追加費用は1回あたり中央値 $0.0136、該当100件で約 $1.5 の**参考推定**。
  残差が推定値と同程度あり、厳密な下限でもない。桁として見れば、
  金額が実装可否の障害になる水準ではない。
