# `auto-bulk-facts` の isolation 失敗の切り分け（2026-09-16）

対象: `9346d19` の実機 B（`run.pCbVjjT9`）で唯一残る実質失敗
`auto-bulk-facts` の `isolation: delegate=[22733, 9861, 8459] direct=20795 fixture=65669`。

保存済みトランスクリプト（`/tmp/ts-ab-2026-09-16/.../run.pCbVjjT9/transcripts/auto-bulk-facts.*.jsonl`）
だけを使った。**追加の課金測定はしていない。** 集計は `judge.Transcript` を
そのまま読み込み、`parent_added_text()` の構成要素を分類したもの。

## 1. 判定の仕組み

`judge.py:2229` の `delegate_lt_direct_and_fixture` は、非 direct の全モードで
`parent_added_utf8_bytes < direct` **かつ** `< fixture` を要求する。1モードでも
外れると、そのケースの4モード全部が fail になる（`:2242-2247`）。
今回外れたのは **auto の1モードだけ**で、haiku / sonnet は direct を 10-12 KB 下回っている。

## 2. 親に入ったバイトの内訳

| モード | 合計 | 最大の内訳 |
|---|---|---|
| direct | 20795 | **fixture 本文 20255（97.4%）** ＋ 親の推論・ツール入力 534 |
| haiku | 9861 | skill 本文 6181 / ツール結果 1130 / 親の推論 1039 / 課題文 990 / 起動文 426 / grep 一致行 84 |
| sonnet | 8459 | 起動文 2825 / 親の推論 2109 / フック拒否・契約文 1814 / ツール結果 1690 |
| auto | 22733 | skill 本文 6150 / 起動メタデータ 4400 / ワーカー戻り 4349 / 親の推論 2914 / 起動文 2357 / 拒否・契約文 1151 / 課題文 990 |

auto の Agent 起動は **4回**（haiku 1回 → sonnet 3回）。1回目が読み取り予算を
使い切り、以降は再試行。CLI が返す `Async agent launched successfully.` の
定型メタデータが 1100 B × 4 = 4400 B、ワーカー戻り 4 本のうち 3 本は
「予算を使い切った」「375行まで成功、next_line=376」という進捗報告である。

auto の 22733 B に fixture の本文は **1行も入っていない**。haiku / sonnet の

## 4. なぜ direct を超えたか

2つが同時に起きた。

1. **基準線が崩れた。** direct の親は全文を読まず、`Grep` と範囲つき `Read` 2回で
   済ませた。引いた本文は 20255 B で fixture 65669 B の **32%** にすぎない。
   同じポリシーの他ケースでは direct が本文をほぼ全部引いている
   （`auto-one-line` 100%、`auto-explicit-multifile` 114%）ので、そちらは
   委譲側が 60 KB 以上の余裕で下回る。
2. **再試行が増幅した。** 予算切れで4回起動したため、skill 本文（1回きり 6150 B）を
   別にしても、起動メタデータ＋起動文＋戻りで 11 KB がオーバーヘッドとして積まれた。

つまり `auto 22733 > direct 20795`（差 1938 B）は、委譲が本文を持ち込んだからではなく、
**賢く振る舞った direct と、再試行を繰り返した auto を、本文と諸経費を区別しない
1つの物差しで比べた**結果である。

## 5. 判定ポリシーの限界（明記）

`delegate_lt_direct_and_fixture` は性質の違う2つの主張を1つの条件に束ねている。

- **(a) 漏洩していないこと**（`< fixture`）— 今回 4 モードとも成立。auto は本文 0 行。
- **(b) 委譲のほうが親の文脈が軽いこと**（`< direct`）— これは費用の主張であって
  隔離の主張ではない。**direct が本文を全部引いたときにしか成り立たない。**
  direct が Grep と範囲読みで済ませられる課題（＝探す文字列が分かっている課題）では、
  委譲側の定型オーバーヘッド（skill 本文 ≒ 6 KB ＋ 起動 1 本あたり ≒ 1.5-2.5 KB）が
  容易に上回る。再試行が増えれば確実に上回る。

したがって `auto-bulk-facts` の isolation 失敗は **フックの欠陥でもスキルの退行でもない**。
今回は直さない。

## 6. 直すとしたら

(a) と (b) を分ける。漏洩判定は `delegate_lt_fixture`（＋本文行の直接照合）に寄せ、
費用判定は別指標にして、再試行回数で正規化するか、direct が実際に引いた本文量を
分母にする。`compare-hook-deny-route` と `compare-edit-dense-lines` は既に
`delegate_lt_fixture` なので、前例はある。

ただしこれは判定器の設計変更であり、既存の基準線の意味が変わる。
`auto-bulk-facts` の予算切れ再試行（`child_status` / `retry_policy` の失敗と同根）を
先に片付けるほうが順序として正しい。再試行が 1 回で収まれば、上の内訳から概算で
auto は 14-15 KB 程度まで下がり、(b) も自然に成立する（実測ではなく差し引きの概算）。
