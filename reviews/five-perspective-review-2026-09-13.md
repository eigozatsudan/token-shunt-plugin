## 真陽性4件

### F1 / P2 — byte制限付きパイプの前段から全文がstderrに戻る

修正前の根拠は `plugin/hooks/check-bash-read:498–516`。末尾が `head -c 1` なら前段の出力経路を確認せず通過していた。

80,001バイトの通常ファイルについて、実Bashとフックを別々に実行して確認した。

| コマンド | 修正前フック | 実出力 |
|---|---|---|
| `cat large.txt` | deny | stdout 80,001 bytes |
| `cat large.txt \| head -c 1` | pass | stdout 1 byte |
| `cat large.txt 1>&2 \| head -c 1` | pass | stderr 80,001 bytes |
| `cat large.txt > /dev/stderr \| head -c 1` | pass | stderr 80,001 bytes |

明示された対応コマンド・通常ファイル・リダイレクトだけで起こり、READMEの「stdout/stderrへ戻る出力先は省略しない」と整合しない。中間 `tee /dev/stderr` も同じ制御の問題として統合した。元担当のP1案から、発生が特定のパイプ形に依存し、ホスト権限を増やす問題ではないことを踏まえP2に調整した。

修正済み: 最終段の制限を迂回する明示的な出力経路を個別に検査し、迂回時は入力のサイズ判定を行う。通常の制限付きパイプ、安全なリダイレクト、引用された演算子風ファイル名を対照として維持した。前段のhead/tail自体が明示ファイルを小さく読む場合と、途中の対応済みbyte limiterがstdinを小さくする場合も過剰拒否しない。後段のlimiterで前段のstderr漏れを免除しない対照も追加した。

### F2 / P2 — Agentの返答が欠落しても返答契約を合格にする

修正前の根拠は `evals/compare/judge.py:965–987`。Agentの対応する tool_result がないと `continue` した後、`child_msg_cap` と `child_no_body` を true にしていた。

プラグイン読み込み、親Agent起動、子Read成功、正常な親最終結果を含む合成ログで、Agent返答だけを欠落させると全体passだった。同じログに4,001文字の返答を追加すると文字数チェックでfailした。ログ欠落が実際に頻発すると仮定する指摘ではなく、証拠がない検査を検証済みとする誤判定である。

修正済み: 親側の対応返答が、Agent起動後かつ親最終結果前に存在することを必須化した。欠落・子イベントへの誤帰属・早着・遅着は `child_result_evidence` で失敗にし、返答契約を合格にしない。

### F3 / P2 — 49/50行writerケースが空・構文不正・親検証未実行でも合格する

修正前の根拠は `evals/compare/cases.json:1188–1196,1214–1224` と `evals/compare/run.sh:281–285`。経路判定以外は通常ファイルの存在しか確認していなかった。

予想行数による委譲経路と、生成物の品質は別の契約である。空Pythonは構文上有効なので、構文確認だけでも不十分。

修正済み: 両経路で対象ファイルへの親 `py_compile` 成功証跡を最終報告前に要求し、ディスク側で構文とケース所定の行数・基本構造を確認する。検証コマンドの文字列をechoするだけの偽証拠や別ターゲットを拒否し、通常のpython/python3とimport別名は対照として許容した。ASTの基本構造確認は、生成コードの実行による完全な機能検証ではない。

- **空白を含む導入先:** `bash -c` で未引用の `${CLAUDE_PLUGIN_ROOT}` を実行する再現はホストと不一致。全フックに `args: []` があり、ローカルCLI 2.1.270は環境変数を文字列置換した単一の実行パスを直接spawnする。親も `/home/dev/.local/share/claude/versions/2.1.270` の埋込JS関数 `bwe`（バイト位置195405500付近）を確認した。同じexec形式では空白入りコピーでもRead/Bashはdenyしたため棄却。
- **先頭リダイレクト、未対応閲覧コマンド、複数呼出の累積:** 対象を限定した現行仕様と一致するため、新規バグとして数えない。
- **走査時間が強制中断ではない:** バイト制限と走査後の経過時間確認はREADMEに明記されている。
- **doctorの未確認項目でも終了0:** 診断の終了コードや記録の意味が現行READMEと一致する。Agent stdinと決定ログの説明には曖昧さが残るが、新規の機能不具合とはしない。
- **ワーカーの書込先制約や生成コード実行:** ホスト権限とモデルへの指示を区別した。新規の攻撃者権限獲得を裏付けられないため、セキュリティ脆弱性には昇格させない。
