# 床を外す — 閾値未満のファイルでの routing（事前登録、2026-09-18）

前の測定 `reviews/plan-phase-routing-2026-09-18.md` は
**両腕とも 0/40** で終わった。**床である。**
本記録はその床を外す設計であって、**まだ走らせていない。**

## 0. 予算（最初に書く。ここで設計が決まる）

上限 $150。累計 **約 $143.9**（`parent-no-read-rate` §0 の $128.4 に、
前ブロックの $15._5_ を足したもの: 初回 1 対 $0.38 + 本体 $15.14）。
**残り 約 $6.1。**

**2 腕 40 対は $15 かかるので、残高では走らせられない。**
そこで本記録は **2 段**に分ける:

- **A: 今の残高で走らせられる、対照腕だけの較正**（約 $5.4、下記 §5）。
  **仮説検定ではない。** 「床が外れたか」だけを見る。
- **B: 2 腕の検定**（約 $15、下記 §9）。**予算の追加判断が要る。**
  **A の結果を見てから B を走らせるかを決める。その決め方も先に書く。**

**A を走らせずに B を走らせない。** 前ブロックは、床の有無を確かめずに
$15.5 を使って 0 と 0 を比べた。**同じ失敗をしないための順序である。**

## 1. 何が床を作ったのか

前ブロックの事後探索（`reviews/plan-phase-routing-posthoc-2026-09-18.md`）:

- **対照腕 40/40 が、委譲の前に Bash を打っていた**
  （`wc` 36、`for` 3、`stat` 1）。**すべて大きさを測る命令である。**
- **deny は 80 run で一度も出ていない。** 親は corpus を読もうとしなかった。

**つまり前ブロックが測ったのは「deny がある世界」ではなく、
「deny を引くほど大きいと、親が読む前に気づける世界」だった。**

**床の候補は「ファイルが大きすぎたこと」である。**
本設計はそこだけを動かす。

## 2. 変えるのは 1 つだけ

| | 前ブロック | 本設計 |
|---|---|---|
| corpus | Django `bc833e8` | **同じ** |
| ファイル数 | 3 | **3** |
| 問いの形 | 呼び出し経路の追跡 | **同じ** |
| `gold` | 3 トークン、1 ファイルに 1 つ | **同じ** |
| **各ファイルが deny を引くか** | **3 件とも引く**（442/707/508 行） | **3 件とも引かない** |
| 合計バイト | 63,527 B | 23,729 B |

**合計は 16,384 B（skill の委譲予算）を超えたままである。**
**「委譲したほうがよい」という助言は残し、「読ませない」という強制だけを外す。**
これが「床を外す」の意味である。

## 5. A: 対照腕だけの較正（残高で走らせられる）

**case は 1 つだけ作る: `django-subthreshold-bare`。**
prompt は前ブロックの `django-plan-trace-bare` と**同じ形**で、
パスと gold だけ差し替える。**委譲を指示しない。**

**n = 25 run。** 1 run 約 $0.215
（前ブロックの case 単価中央値 $0.153 + run あたり諸経費 $0.062）。
**見込み $5.4。枠 $5.70、reserve $0.30。**

```
SUITE=X SLOTS=django-subthreshold-bare/auto \
bash evals/compare/drive.sh --pairs 25 \
    --cases django-subthreshold-bare \
    --cap 5.70 --reserve 0.30 --max-barren 5
```

**A は検定ではない。** 出すのは **率と Wilson 95% CI だけ**である。
n=25 の CI は広い（率 0.30 なら概ね [0.15, 0.51]）。
**A に p 値を付けない。**

### 5.1 A を見て B をどうするか（走らせる前に決める）

**Wilson 95% CI の下限で決める。点推定では決めない。**

- **下限 > 0.05** → **床は外れた。** B は 2 腕を比べる意味がある。
  **予算の追加を人に諮る**（B は約 $15）。
- **下限 ≤ 0.05**（0/25 を含む。0/25 の CI は [0.000, 0.134]）
  → **床は deny 閾値のせいではなかった。**
  **B をこの形で走らせない。** 床の原因を別に探す（§8）。

**この分岐は今決めている。A の数字を見てから動かさない。**

## 6. 予測（A について、外したときの書き方も含む）

**予測: 対照腕の FAIL 率 0.15〜0.40。**
根拠は `parent-no-read-rate-2026-09-17.md` の 21.7% で、
**あちらの fixture も deny を引かない大きさだった**（22,546 B）。
**その点推定を解析には使わない。今回も対照は同時に取る。**

- **予測どおり（下限 > 0.05）**なら、
  「**deny が出ない大きさでは、親は本文を自分で読むことがある。**」
  **「SDD なら直る」とは書かない。**
- **0 に近かった**なら、
  「**床は deny 閾値では説明できない。**」と書き、
  **`parent-no-read-rate` の 21.7% は書き換えず並べて残す。**
  違いの候補（モデルの版、prompt の形、ファイルの種類）を
  **数えられる形で挙げるだけにし、$0 の事後探索へ回す。**

**ここに書いた閾値と文言は今決めている。後から動かさない。**

## 7. 打ち切り

- `--cap 5.70 --reserve 0.30`。**残高 $6.1 を超えない。**
- `--max-barren 5`。
- `--max-runs` は既定（目標の 2 倍 = 50）。**厳しいほうが先に効く。**
- prompt の md5 を毎 run 照合（`drive.sh`）。
- **枠に達したらそこまでで報告し、後から足さない。**
  **達成した n を率と一緒に必ず書く。**

## 8. 事前に認めている弱点

- **A は 1 腕であり、比較ではない。** 「計画文書が効くか」には答えない。
  **答えるのは B であって、B は走らせる保証が無い。**
- **n=25 の CI は広い。** 0.15〜0.40 のどこであっても
  CI は 0.2 幅を超える。**点推定を結論にしない。**
- **床の原因が「大きさ」だと決めつけている。**
  ほかに `wc` を打つ癖そのもの、問いの形（経路追跡）、
  モデルの版がありうる。**A はそのうち 1 つしか動かさない。**
- **ファイルの選択は私が行った。** 3 件とも閾値未満になるよう選んだ。
  **意図的だが、Django の代表値ではない。**
- **case は 1 つ、corpus は 1 つ、言語は 1 つ。**
- **費用の問いには答えない**（`direct` 腕が無い）。
- **モデルは知識で答えられるかもしれない。**
  `show_list` / `applied_migrations` / `forwards_plan` は
  公開された Django の名前である。**読まずに当てた run と
  読んで当てた run を、`accuracy` だけでは分けられない。**
  **主要は `parent_no_read` なのでこの弱点は主要に影響しないが、
  「委譲しても答えられたか」は前ブロックより弱い主張になる。**
