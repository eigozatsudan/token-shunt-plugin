# deny 本文の転送率を通常運用で数える（2026-09-15、課金なし）

`sendback-worker-repair-2026-09-15.md` §6.1 で直した欠陥
──親が deny テンプレートを丸ごと子のプロンプトに写す──の効果を、
**専用測定を組まずに**数えるための計器と、その時点の値。

## 1. 何を分母にするか

`evals/compare/prompt_forwarding.py`（モデルは起動しない）。
保存セッションの `bulk-reader` 起動を1件ずつ見て、親が渡したプロンプトに
`do not read these paths yourself` が入っているかを数える。

分母は**起動数ではなく「deny を渡された起動数」**にした。
利用者が直接 Agent を指示した起動は、写す本文をそもそも持っていない。
セッション本文に `Delegate now` があるかで判定する。

## 2. 現時点の値

| 期 | 起動 | うち deny を渡された | 転送 | 応答形式の復唱 |
|---|---|---|---|---|
| `da6e4d3` 以前 | 468 | 109 | **19 (17.4%)** | 362 (77.4%) |
| `da6e4d3`（復唱をやめた） | 102 | 69 | **2 (2.9%)** | 0 (0.0%) |
| `ea00cd6`（自己転送を禁じた） | 3 | **0** | — | 0 (0.0%) |

- `da6e4d3` は復唱を 77.4% → 0% にし、副作用として転送も 17.4% → 2.9% に下げた。
  ただし**ゼロにはならなかった**。これが `ea00cd6` を入れた理由である。
- `ea00cd6` 以降の3起動は、いずれも誘発プローブで**親に deny が出ていない**。
  つまり **`ea00cd6` の効果はまだ1件も測れていない**（分母0）。

## 3. いつ読めるようになるか

分母は通常の実行で貯まる。`evals/compare/run.sh` の A/B スイートは
deny 経路を通るケースを含むので、次に一通り回した時点で deny 起動が数十件つく。
そこで同じコマンドを実行し、この表の3行目を埋める。

```
python3 evals/compare/prompt_forwarding.py
```

判定基準：`da6e4d3` 期の 2/69 (2.9%) が基準値。
deny 起動が 50 件を超えても転送 0 なら、改善したと言ってよい。
1件でも出たら、テンプレートの文面では足りないということなので、
プロンプト組み立てを親の判断に委ねない形（deny 本文と worker プロンプトの分離）を検討する。

## 4. 限界

- セッションは**最終書き込み時刻**で期に割り振っている。コミットをまたいだ実行は
  後の期に入る。この件数では誤差であって偏りではない。
- 転送の検出は固定文字列1つ（`do not read these paths yourself`）。
  テンプレートの文面を変えたら、この計器も合わせて直す必要がある。
  テストで文字列と期の割り振りを固定してある（`test_prompt_forwarding.py`）。
