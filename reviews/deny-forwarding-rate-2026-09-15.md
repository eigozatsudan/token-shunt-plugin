# deny 本文の転送率を通常運用で数える（2026-09-15、課金なし）

`sendback-worker-repair-2026-09-15.md` §6.1 で直した欠陥
──親が deny テンプレートを丸ごと子のプロンプトに写す──の効果を、
**専用測定を組まずに**数えるための計器と、その時点の値。

## 1. 何を分母にするか

`evals/compare/prompt_forwarding.py`（モデルは起動しない）。
保存セッションの `bulk-reader` 起動を1件ずつ見て、親が渡したプロンプトに
`do not read these paths yourself` が入っているかを数える。

分母は**起動数ではなく「deny を渡された起動数」**にした。
利用者が直接 Agent を指示した起動は、写す本文をそもそも持っていない。
セッション本文に `Delegate now` があるかで判定する。

## 3. いつ読めるようになるか

分母は通常の実行で貯まる。`evals/compare/run.sh` の A/B スイートは
deny 経路を通るケースを含むので、次に一通り回した時点で deny 起動が数十件つく。
そこで同じコマンドを実行し、この表の3行目を埋める。

```
python3 evals/compare/prompt_forwarding.py
```

判定基準：`da6e4d3` 期の 2/69 (2.9%) が基準値。
deny 起動が 50 件を超えても転送 0 なら、改善したと言ってよい。
1件でも出たら、テンプレートの文面では足りないということなので、
プロンプト組み立てを親の判断に委ねない形（deny 本文と worker プロンプトの分離）を検討する。

## 4. 限界

- セッションは**最終書き込み時刻**で期に割り振っている。コミットをまたいだ実行は
  後の期に入る。この件数では誤差であって偏りではない。
- 転送の検出は固定文字列1つ（`do not read these paths yourself`）。
  テンプレートの文面を変えたら、この計器も合わせて直す必要がある。
  テストで文字列と期の割り振りを固定してある（`test_prompt_forwarding.py`）。

### 5.1 分母そのものの点検

`deny_served` は「セッション本文に `Delegate now` があるか」というファイル単位の
判定なので、次の3つを別に数えて確かめた。

1. **引用による偽陽性** — 契約ファイルを Read しただけ、会話が拒否文を引用しただけの
   出現。→ 該当 **0**。マークを含む 236 セッションはすべて、本物の deny が
   `tool_result` として届いている。
2. **順序** — 起動より**後**に届いた deny を数えていないか。→ 全 270 件の
   「deny を渡された起動」で、deny の行番号が起動の行番号より前。差異 **0**。
3. **期の割り振り** — §4 が「最終書き込み時刻で割り振る」と断っていた件。
   各セッションの最初と最後のイベント時刻で期を計算し直しても、
   mtime による割り振りと**一致（不一致 0、コミットをまたぐセッション 0）**。

分母の作りに問題は見つからなかった。§4 の限界は残るが、この標本では発現していない。

### 5.2 判定

§3 の事前基準は「deny 起動が 50 件を超えても転送 0 なら、改善したと言ってよい」。
**92 件で 0 件なので、基準は満たしている。**

ただし統計的な分解能は正直に書いておく。

| 期 | 転送率 | 95% 信頼区間（Wilson） |
|---|---|---|
| `da6e4d3` 以前 | 17.4% | 11.5% – 25.6% |
| `da6e4d3` | 2.9% | 0.8% – 10.0% |
| `ea00cd6` | 0.0% | 0.0% – **4.0%** |

- `da6e4d3` 以前 vs `da6e4d3`: Fisher p = 0.0034（差は本物）。
- `da6e4d3` vs `ea00cd6`: Fisher p = 0.18。**この2期は区別できない。**
- 0/92 が除外できるのは「真の転送率が 4% 超」までで、直前の期の 2.9% は
  その中に入る。2.9% との差を p<0.05 で言うには deny 起動が **約 300 件**要る
  （0/300 で p=0.035、0/200 では p=0.065）。

つまり `ea00cd6` について言えるのは「事前に決めた基準は満たした」であって、
「`da6e4d3` より良いことを示した」ではない。分母は通常運用で貯まり続けるので、
次に A/B を回したあとで同じコマンドを実行し、300 件に近づいたところで
この判定を更新する。
