## 2. 判定

事前登録 §5-1: **M1 = 0 なので厳格化はしない。**
観測されない形のために、固定 N プローブが測った block 率
（S1 誤 block 0 件）を動かす理由が無い。§11.1 の混在パス問題は、
「そういう報告が出たら考える」ではなく
**「出ないことを 6 本分測ったので、今は変えない」**として閉じる。

3 の法則で上限のみ: 0/6 は 95% 上限 **0.39**。低い基準率を否定できる強さは
無い。混在が実際に 1 割程度で起きるなら 6 本では見逃す。
段階 2（厳格化した腕）は走らせない。必要になったらこの記録の分母から
やり直す。

## 3. M2 について（`a69d1f9` の副次的な確認）

全相対の報告も 0 件だった。§1 sonnet では sonnet ワーカーの 3 行すべてが
相対パスだったが、今回 sonnet 枠は 2 周とも 4 行すべて絶対パスである。

**これを「`a69d1f9` が直した」とは書かない**（事前登録 §5-3）。
§1 の観測は 1 run であり、基準率ではない。腕も 1 本しかないので、
契約変更前の同条件と比べていない。言えるのは
「契約変更後の 6 本ではその形が出なかった」だけである。

## 4. 事前登録との差（記録）

§3 は「1 run に複数起動があるので報告数は run 数より多い」と予想していたが、
**実際は 1 run 1 起動**で、報告数は run 数と同じ 6 本だった。
事前登録 §5-4 の下限（判定可能な報告 6 本）にちょうど届いた形になる。
分母を厚くしたいなら枠を増やすか周を増やす必要がある。

verdict は 6 run とも `isolation: direct=None`（枠に direct を入れていない
既知の制約）。それ以外の判定名では 2 周目の 3 枠すべてが pass。
