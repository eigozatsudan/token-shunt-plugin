## 2. 判定

事前登録 §4-1 の条件（N5 ≥ 1 かつ N1 = 0）を満たす。

N5 が重要である。N1 = 0 だけなら「偽拒否が無い」と「スコープが常に空で
検査が死んでいる」を区別できない（E2b で実際にやった誤り）。今回は
**6 起動すべてでスコープが 3 パスに解決され、その 3 パスがそのまま読まれた**
ので、検査は経路として生きたうえで 1 本も拒否していない。

3 の法則で上限のみ: 起動を分母に取れば 0/6 で 95% 上限 **0.39**、
Read を分母に取れば 0/18 で **0.15**。低い偽拒否率を否定できる強さは無い。
§14.3 に記録した形（空白を含むパス、相対で書かれた宣言）は今回の枠には
出てこない。**その形が出ないことを測ったのではなく、出ない枠で測った**という
違いは残る。

## 3. 効果（再読の阻止）は測っていない

事前登録 §1 のとおり、ここで測ったのは偽拒否だけである。
§4 の「2 起動目が前起動の alpha を再読した」は 1 run の観測であり、
基準率ではない。今回の 6 run では 1 run 1 起動の枠が多く、
**そもそも再読が起こりうる状況（同一 run 内の 2 起動目）が
`compare-explicit-multifile` の 2 起動分しか無い**。
阻止の効果を主張するには、複数起動を強制する枠で別に測る必要がある。
本記録では主張しない。
