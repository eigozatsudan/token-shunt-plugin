## 4. 事前登録の見込みが外れた点（重要）

### 4.1 試行の発生率

**0.12 件/run を採って 70 run で約 8.4 件**と見込んだ。
実際は treatment 0.40 件/run、control 0.20 件/run で、**21 件**出た。

前回 §4.1 で「50 run では 0.12、既走 30 run では 0.30」と揺れを記録し、
**低いほうを採る**と決めた。安全側に倒した判断そのものは間違っていない。
**外れたのは率の予測であって、方針ではない。**

### 4.2 「拒否は手を伸ばす頻度を変えていない」が崩れた

これは前回まで、腕の比較可能性の根拠として書いてきた項目である（事前登録 §5-3）。

| | treatment | control | p |
|---|---|---|---|
| 試行 / 機会（交互 120 run） | 18/54 = 0.33 | 9/55 = 0.16 | **0.048** |
| 試行 / 機会（全 150 run） | 22/68 = 0.32 | 14/75 = 0.19 | 0.082 |

**N が増えたら有意に近づいた。向きは「treatment のほうが多く手を伸ばす」。**

小 N では p = 0.77 / 1.00 で「変わっていない」と書いた。
**あれは効果が無かったのではなく、検出力が無かったのである。** 訂正する。

考えられる機構: 拒否されたワーカーが partial を返し、親が別の起動を立て、
そこでまた手を伸ばす。**拒否が試行を生む**なら、
`成立/試行` の分母は treatment 側で膨らむ。

**だが主要の結論は壊れない。** 分母に依存しない
`成立/機会`（0/54 対 8/55、p = 5.9e-03）で、機会の数は両腕ほぼ同数（54 対 55）である。
**「成立が 0 件」は分母の取り方に依らない。**

## 6. 費用上限を破った（$30 → $36.55）

**事前登録 §2 は本段階の上限を $11.5、総額の見込みを $28.2 と書いた。
実際はブロック 2 だけで $19.0829、累計 $36.55 である。**

原因は 2 つで、どちらも私の側にある。

1. **単価の見積りが低かった。** ブロック 1 の実測 $0.1522/run をそのまま使ったが、
   ブロック 2 は **$0.2726/run**。試行が増えれば起動も増え、起動が増えれば費用が増える。
   **§4.1 で「発生率は倍以上揺れる」と自分で書きながら、
   費用をその揺れに連動させなかった。**
2. **止める仕掛けを作らなかった。** 事前登録には「超えたら途中でも止めて、
   走った分だけ記録する」と書いたが、**70 run を 1 本のループで流し、
   途中で費用を見る手順を入れなかった。** 書いた停止規則が実行されていない。

**隠さずに書く。上限は守られなかった。**

今後の課金では、**run ごとに累計費用を見て上限で抜ける**ようにする。
（`reviews/` の先例に「見積りを書く」はあったが「止める手順を作る」は無かった。
見積りは書けば済むが、停止は仕掛けが要る。）
