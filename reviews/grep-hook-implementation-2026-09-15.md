# Grep の2規則をフックにした（2026-09-15、追加課金なし）

`reviews/enforcement-design-2026-09-15.md` §1 の調査を実装に落とした記録。
同 §1.6 に残っていた未解決の設計判断を決め、その根拠を残す。
**実装・オフライン検証のみで、実機の課金測定は行っていない**（§5）。

## 1. 入れたもの

| ファイル | 役割 |
|---|---|
| `plugin/hooks/grep_bounds.py` | 判定ロジック（`decide` / `record` / `is_measured` / `metadata_paths` / `target_file`） |
| `plugin/hooks/check-grep-bounds` | 実行形。`PreToolUse: Grep` で判定、`PostToolUse: Bash` で計測を記録、`--sized` で Read deny 由来のサイズを記録 |

§1 の調査どおり **2規則は1本のフック**で扱える。判定順は
「Grep か → content か → 対象が単一の実在ファイルか → 予算超過か →
拒否上限か → 計測済みか → 形式は満たすか」である。

## 2. §1.6 の未解決判断をこう決めた

### 2.1 警告ではなく拒否

`reviews/behaviour-measurement-2026-09-15.md` が
「文言を足しても4件中3件は行動が変わらない」ことを実測している。
`additionalContext` はその文言と同じ強度しか持たない。
**このフックを入れる理由そのものが警告では満たされない**ので拒否にした。

### 2.2 対象は単一の実在ファイルだけ

ディレクトリ・`path` 省略・`glob` 併用・存在しないパスは判定しない。
**抜け道が残ることは承知のうえ**である（§1.2）。
理由は、サイズ比較が対象の確定を前提にしており、
glob 展開のコストが読めないため。実測45実行の親 Grep 20件は
全件が単一ファイルだったので、初版はここを押さえる。
ディレクトリ検索を塞ぐなら別の判定基準が要る。

### 2.3 Read deny 由来のサイズ既知も「計測済み」とみなす

§1.4 が指摘したとおり、**計測の有無とルート判断の有無は同じではない**。
`check-file-size` の拒否本文はサイズを実際に告げている。
それを読んだ親に `wc -c` をもう一度走らせるのは、
規則の目的（本文より先にメタデータ）を満たしているのに往復だけ増やす。
そこで `check-file-size` 側から `--sized <abs>...` を渡して記録する。
**契約テンプレートが `(N B)` を描画したパスに限る**（サイズを告げていない
fallback 経路では記録しない）。

### 2.4 状態が失われたら未計測として扱う（fail-closed）

セッション再開・compact で状態は消える。ここで素通しすると
**規則が黙って失効する**。代償は `wc -c` の1往復（§1.5 の見積りで約 $0.013）
なので、拒否側に倒した。同じ理由で、inode・サイズ・更新時刻のいずれかが
変わっていれば計測は無効になる。

### 2.5 拒否は6回で打ち切る

拒否の往復だけでトークンを使い切る形を避けるため、
同一 `(session_id, agent_id)` での拒否が `DENY_CAP = 6` に達したら、
再試行を促さず「部分的な結果で報告するか `bulk-reader` に委譲せよ」という
終了指示に切り替える。6は §1.5 の「実行あたり判定対象 0.44 件」に対して
十分な余裕があり、かつ暴走を止められる値として置いた。**実測値ではない。**

## 3. 実装上、調査時に見えていなかった点

- **登録の `args` に依存しない。** 当初は `"args": ["--bash"]` で
  記録モードを渡す形にしたが、CLI が `args` を無視した場合、
  **何も記録されないまま全 Grep が拒否される**。
  実行形は `hook_event_name` / `tool_name` から自分でモードを決める。
- **`metadata_paths` はシェル展開を一切認めない。**
  `$F`・`` ` ``・`;`・`&&`・`*` などを含むコマンドは記録しない。
  展開後に何を計測したのか分からないものを「計測済み」にはできない。
- `stat -c %s -- /path` の `%s` を operand と誤認した。
  値を取るオプションはコマンド別に持つ（`wc` の `-c` は値を取らない）。

## 4.1 実装後に見つかって直した2件（2026-09-15）

- **相対パスがフックの cwd で解決されていた。** `check-file-size:238` /
  `check-bash-read:248` と同じく、stdin JSON のトップレベル `cwd` が絶対パスなら
  そこへ移ってから判定する。直す前は、セッション cwd にある `big.txt` を
  フックの cwd から見て存在しないと判断して**素通し**し、フックの cwd に同名の
  小さいファイルがあれば**そちらを判定して予算内として通していた**。
  不正な `cwd` は Read 側と同様に deny。ただし記録経路（PostToolUse / `--sized`）は
  拒否しても意味が無いので、絶対パスだけを記録する。
- **`token-shunt:code-writer` を `bulk-reader` へ誘導していた。**
  writer の tools は Read / Write / Grep / Glob で Bash が無く、
  `check-file-size` は writer の Read をサイズ免除する。
  つまり writer には**計測手段が無い**（成功した Read は計測に数えない）。
  拒否上限に達したとき、writer には持っていない経路を指示しないようにし、
  拒否本文も `wc -c` ではなく `files_with_matches` / 範囲 Read を案内する。
  **残る制限**：writer の予算超過ファイルへの content Grep は依然として通らない。
  `files_with_matches` / `count` / Read→Write は従来どおり通る。
  計測規則そのものを writer で免除する案（設計調査の案2）は採っていない。
