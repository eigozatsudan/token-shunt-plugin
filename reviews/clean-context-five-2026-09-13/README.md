### F1 — P2: EOFメタデータが末尾改行のない最終行を落とす

位置: [bulk-reader/SKILL.md:51](/home/dev/projects/skills/token-shunt/plugin/skills/bulk-reader/SKILL.md:51)、継続契約は同105行以降。

親は `wc -lc` の行数を子へ渡し、子はそれをEOFとして読み取りの継続を判断する。しかし `wc -l` は改行数であり、未終端の最終行を数えない。2,000個の改行と未終端の最終行を持つ82,023バイトのファイルで、供給行数2,000・論理行数2,001を統合側でも再現した。

Readが2,000行までを成功として返したとき、供給EOFに達したように見え、最後の定義・設定を見落とした不存在回答につながり得る。無通知の早期終了はスキル自身が対応を要求する経路で、末尾改行必須という制限はない。

**確定したのはメタデータと継続契約の不整合。実モデルの誤回答は未検証。** LF数に「非空かつ最終バイトがLFでなければ1」を足す等、Readの行番号と一致する行数を渡す必要がある。

### F2 — P2: 同一メッセージIDの別内容を捨て、隔離量と本文漏れを過少判定する

位置: [judge.py:308](/home/dev/projects/skills/token-shunt/evals/compare/judge.py:308)、影響先は `metrics()` と `leakcheck()`。

`parent_added_text()` は同一 `message.id` の親assistantイベントを最初の1件だけ採用する。同じAPI応答から複数のツール内容が別イベントとして届いた場合、後続の `Agent.prompt` 等を集計対象から落とす。

統合側の対照実験では、短文に続く2,100バイトのツール引数を同一IDにすると、親本文量20バイト・`leakcheck: clean` となった。内容を変えずIDだけ分けると2,172バイト・`>2KiB contiguous quote` を検出した。

同一応答の複数メッセージがIDを共有すること、使用量の重複排除にIDを用いることは[公式の使用量追跡仕様](https://code.claude.com/docs/en/agent-sdk/cost-tracking#track-per-step-usage)でも説明される。使用量の同一性と本文ブロックの同一性は別に扱う必要がある。保存済み実機ログにも同一IDの `thinking` → `tool_use` 等の別内容イベントがあり、この形式が実際に存在することを確認した。今回の漏れ見逃しの対照実験は合成入力を使用した。
