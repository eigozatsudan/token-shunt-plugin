## 1. 結論

**追いかけていた形は、もう主要な形ではなかった。**

漏れた path は 31 件（1 arm で複数 path が漏れる）。内訳:

| 形 | その arm は何か委譲したか | 件数 |
|---|---|---|
| 一度も委譲せずに親が読んだ | **していない（Agent 0 回）** | **17** |
| 一度も委譲せずに親が読んだ | している（別の path を委譲） | 8 |
| 委譲した後に親が読んだ | している | 4 |
| 委譲する前に親が読んだ | している | 2 |

**deny は 31 件すべてで一度も出ていない。**

右列が「している」の 14 件は、**現行条文が名指ししている形**である
（質問の path のうち大きいものだけ渡し、小さいものを親が抱えた）。
左の 17 件は **worker を一度も呼んでいない** arm で、
委譲の分け方を論じる条文はそもそも当たらない。

arm 単位では、FAIL 13 arm のうち **6 arm は Agent 呼び出しが 0 回**。
pass した 47 arm は**全て 1 回以上委譲している**。

| | agents=0 | agents≥1 |

| FAIL | 6 | 7 |
| pass | 0 | 47 |

## 2. なぜ形が変わったのか — fixture が縮んでいた

`user.rb` は **22,546 bytes** である。Read hook の閾値は 65,536 なので、
**この case では deny が原理的に出ない。**

archive（2026-09-13/14）では同じ file が **67,180 bytes** で、
`bytes=67180/65536` の deny が出ていた。縮んだのは
`4c2fa1e`（2026-09-14、"Fix sixteen review findings…"）である。

つまり:

- Django と archive で見た漏れは、**deny が出る世界**の話だった。
- 今日の 20 run は、**deny が出ない世界**を測っていた。
  3 つ合計 22,806 bytes は step 1 の 16,384 を超えるので委譲すべきだが、
  それを強制する機構は無く、**条文だけが根拠**になる。

`reviews/parent-no-read-rate-2026-09-17.md` の 21.7% は、
**「deny の出ない case で、条文だけを頼りにしたときの率」**と
読み直す必要がある。率そのものは正しいが、一般化の範囲はそれだけ狭い。

## 3. 今日の条文修正が当たらなかった理由

覆う範囲は条文によって違う:

| 条文 | 覆う件数 |
|---|---|
| `c87055a`/`66a952f`「委譲した後で読むな」 | 4/31 |

| （どの条文も当たらない：委譲 0 回） | 17/31 |

現行条文でも**過半に届いていない。** 残る 17 件は worker を
一度も呼んでいない arm で、これは「委譲の分け方」の問題ではない。

私は 2 度とも、形を見ずに条文を書き直した。

これは「委譲0回」として既知の事象でもある
（`reviews/zero-delegation-2026-09-13.md`、当時 6 件を調査）。
そこでも原因は単一ではなく、小仕事規則による親生成と
Grep 経由の正答が主だった。

**3 つ目の形も見えた。** `run.WYiYiQXm` の haiku arm は、
予算超過の `user.rb` に `output_mode=content` の Grep を掛けて
`check-grep-bounds` に拒否され、**境界付きで掛け直して通し**、
その結果で 529 行目を特定して `Read(offset=525, limit=15)` を撃っている。
これは SKILL.md の description が名指しで禁じている
`never use it to fetch the answer or to discover a range and claim the
known-range exception` そのものである。
**hook は境界付き Grep を設計どおり通す。**
