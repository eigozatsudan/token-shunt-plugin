## 1. なぜ片腕なのか

## 2. 何を言えて、何を言えないか（先に書く）

言える:
- 「treatment ビルドで機会 N 件のうち M 件で範囲外の Read が試みられ、
  **そのうち何件が読み切られたか**」。M 件すべてが拒否なら、
  成立率の 95% 上限は約 3/M（rule of three）。
- 偽拒否が何件あったか。

**言えない**:
- **「拒否が再読を減らした」とは言えない。** control 腕を走らせないので、
  再読の起き方自体が変わったのか、起きたが止まったのかを分けられない。
- 段階 1 の control データ（機会 1 → 試行 1 → 成立 1）は**N = 1 の参考値**として
  併記するだけで、**比較の分母として扱わない。p 値は出さない。**
- 「この予算では両腕が買えなかった」という事実を、
  結果の書き方でごまかさない。**表題に「片腕」と書く。**

## 4. 事前登録する項目

単位は**機会**。

| # | 項目 | 定義 |
|---|---|---|
| C1 | 機会 | 前の起動が触れたパスのうち宣言に無いものがある起動の数 |
| C2 | 試行 | C1 のうち範囲外 Read を試みたもの |
| C3 | 成立 | C1 のうち範囲外を読み切ったもの。**期待値 0** |
| C4 | スコープ拒否 | 拒否文言で止まった Read の数 |
| C5 | 偽拒否 | 宣言集合内のパスが拒否された件数。**期待値 0、1 件でも製品の後退** |
| C6 | 拒否のあと | 拒否を受けた起動の内訳: partial 報告 / budget 使い切り / 別パスへ / 停止 |
| C7 | 合否 | 枠の verdict |
| C8 | 費用 | run ごとの最終 `total_cost_usd` の和 |

書き方の規則（事前）:

1. **C3 = 0 でも「再読は不可能」とは書かない。** 「12 run のこの枠で、
   M 件の試行が 1 件も通らなかった」と書く。
2. **C5 ≥ 1 は後退。** C3 が 0 でも「入れてよい」とは書かない。
3. **C2 = 0 なら測定は失敗である。** 「阻止された」ではなく
   「試行が観測されなかったので、阻止したかどうか分からない」と書く。
   段階 1 の機会あたり試行率（1/4）から、12 run で C2 = 0 は起こりうる。
4. 中間解析はしない。12 run を全部走らせてから数える。
5. rule of three を使うときは**分母が試行であって機会ではない**ことを明記する。
