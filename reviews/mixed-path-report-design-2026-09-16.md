# 混在パス報告の基準率測定・事前登録（2026-09-16）

`reviews/a-suite-failures-9346d19-2026-09-16.md` §11.1 が残した問いを測る。
**本記録は走らせる前にコミットする。** 項目・N・判定基準は事前に固定し、
結果が出てから基準を動かさない。

## 1. 問い

今の SubagentStop は、**使える絶対パスを持つ行が 1 本も無い**報告だけを
送り戻す（`check_child_items`）。一部の行だけ相対パスの「混在」報告は
ok として通り、相対行は親側の契約で `unconfirmed:` に落ちる。

これを「1 行でも相対なら送り戻す」に変えるべきか。変えれば block 率が動き、
固定 N プローブが測った S1（誤 block）0 件は測り直しになる。

**変更の前に、混在がそもそも起きるのかを測る。** 起きないものを直すために
測定済みの挙動を動かすのは割に合わない。

## 2. 段階を分ける

- **段階 1（本記録）**: 基準率だけを測る。**腕は 1 本**（現行 HEAD）。
  厳格化の実装はしない。
- **段階 2（条件付き）**: 段階 1 で混在が 1 件でも出たときだけ、厳格化した
  腕を作って修復率と誤 block を測る。**別の事前登録と別の予算**とする。

段階 1 で 0 件なら、段階 2 は走らせない。

## 3. 条件

枠は 3。いずれもワーカーが複数行の `confirmed:` を返す委譲枠。

- `compare-explicit-multifile/haiku`
- `compare-explicit-multifile/sonnet`（§1 で 3 行とも相対パスだったモード）
- `auto-explicit-multifile/haiku`

**2 周 × 3 枠 = 6 run。** 1 run に複数起動があるので、報告数は run 数より多い。
`SENDBACK` は既定の off。段階 1 は報告の**形**を数えるだけで、送り戻しの
発火は関係しない。むしろ入にすると全相対の報告が書き直されて基準率が歪む。

## 4. 事前登録する項目

計器は `evals/compare/retention_probe.py` の `report_shape()`
（本コミットに同梱、テスト 6 件）。単位は **run ではなく報告**。

| # | 項目 | 定義 |
|---|---|---|
| M1 | 混在 | 使える絶対パスの行と、絶対でない行の**両方**を持つ報告数 |
| M2 | 全相対 | 使える行が 0 で、絶対でない行がある報告数（§1 sonnet の形） |
| M3 | 全絶対 | 契約どおりの報告数 |
| M4 | 判定不能 | パスは絶対だがファイルが消えている報告数（分母から外す） |
| M5 | 費用 | run ごとの `total_cost_usd` |

M4 を違反に数えない。評価の一時ツリーは走行後に消えるので、
片づけを契約違反と読むと基準率を捏造することになる。

## 5. 判定基準（事前）

判定可能な報告（M1 + M2 + M3）を分母とする。

1. **M1 = 0 なら、厳格化はしない。** §11.1 を「観測されない形のために
   測定済みの block 率を動かさない」と結論して閉じる。
   3 の法則で上限だけ記録する（0/10 なら ≤ 0.30）。
2. **M1 ≥ 1 なら段階 2 に進む。** 本記録では結論を出さない。
3. **M2 は `a69d1f9`（契約が絶対パスを要求）の副次的な確認**として記録する。
   §1 sonnet では sonnet ワーカーの 3 行すべてが相対だった（1 run）。
   M2 = 0 でも「直った」とは書かない。1 run の観測は基準率ではない。
4. 判定可能な報告が 6 本未満なら、**基準率は出さない**。枠がワーカーを
   起動していないということなので、枠選びの失敗として記録する。
