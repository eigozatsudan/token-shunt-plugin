# 対照実行 A/B：`auto-explicit-multifile`（2026-09-15）

同一 fixture・同一プロンプトで、ケース単独実行を各3周。

- **A = v2 のみ**（description 修正済み、応答契約は従来どおり
  `hooks/reader-call-contract` が親に書かせる）
- **B = v2 ＋ 応答契約の子側移設**（contract から
  「prompt must contain: …"One bullet per fact…"」を削除し、
  `agents/bulk-reader.md` の system prompt に既にある規定に委ねる）

退行 description に契約移設だけを加えた版、および Skill 本文の読み込み回避は
指示により実施していない。後者は worker-model 解決に影響するため保留。

## 0. 比較条件の限定

### 旧測定との非互換

A/B の `direct` は $0.1124〜0.1132、cacheW 約 24000。
`reviews/multifile-cost-2026-09-15.md` §1 の `direct` は $0.0210〜0.0219、
**cacheW 0**。fixture もプロンプトも同一で、違いはキャッシュ状態である。
旧測定は225実行のスイート内で走っており温まったキャッシュを読んでいたが、
A/B はケース単独実行のためキャッシュ生成を自分で払う。
**したがって A/B の金額を旧測定の §1〜§3 と比較してはならない。**

### A と B のキャッシュ条件は揃っている（確認済み）

単独実行という条件だけでは不十分で、B は A の後に走っているため
A が作ったキャッシュを再利用している可能性があった。両腕が変更していない
`direct` で確認する。

| 腕 | 周 | direct cacheR | direct cacheW |
|---|---|---|---|
| A | 1 / 2 / 3 | 52560 / 52560 / 52566 | 23975 / 23975 / 23984 |
| B | 1 / 2 / 3 | 52607 / 52607 / 52607 | **24022 / 24022 / 24022** |

B の cacheW は A と同水準（差 +47、+0.2%）。B が A のキャッシュに
乗っているなら cacheW は大きく減って cacheR が増えるはずで、
そうなっていない。

**この根拠の範囲**: これは `direct` のキャッシュ量に A/B で大きな条件差が
無いことを示すもので、**委譲経路を含めて「再利用なし」と断定するものでは
ない**。`direct` は子を起動せず、プラグイン読み込みも経ないため、
委譲側で生じるキャッシュ（スキル本文・contract・子の文脈）の再利用状況は
この指標では見えていない。

### 「比較条件を満たす」の定義

`gold_confirmed` は本プラン以前からの既知失敗（12実行で `confirmed:` 項目に
絶対パスが付いた例が0件）であり、両腕の全委譲実行で落ちる。
本比較で言う**「条件を満たす実行」とは、既知の `gold_confirmed` 失敗を除いた
うえで、ルーティング（親の本文先読みなし）と実行契約（子の読み取り回数、
requested/resolved model、retry 方針）を満たした実行**を指す。
「契約遵守」一般を意味しない。

## 4. 結論

1. **契約移設は目的（重複の除去）を達成した。** 3周・全モードで再出力が
   消え、ハーネスは 125 pass / 0 fail。契約の二重管理も解消した。
2. **費用削減効果は未証明。** 理論値 $0.0009 に対して観測ばらつきが
   $0.0567 で、この設計の測定では検出できない。追加周回でも費用面の
   決着は見込み薄。
3. **次に優先すべきは worker-model 解決の再発**（A で 2/3）。
   費用面でも、全実行平均の差 $0.015 に再試行が寄与しており、
   229 chars の削減より一桁大きい規模である。

## 4.1 B 周2 の `None` → `haiku` が比較条件を満たす理由

B 周2 の auto は Agent を2回呼んでいる。判定の分かれ目は、
**モデル省略が正規の解決手順なのか、失敗後の再試行なのか**である。

記録上は後者だが、**フックが起動前に止めた**種類の再試行である。

```
Agent(model=None)  → 却下（launch_rejected: true, requested_model: null）
  "token-shunt: Agent model must be explicitly haiku or sonnet.
   Resolve --worker-model first (auto starts with haiku);
   resend the same call with model set.
   This denied launch is not evidence for escalation."
Agent(model=haiku) → 起動（launch_rejected: false, status: complete）
```

- **ワーカーは一度も不正なモデルで起動していない。** 1回目は
  `launch_rejected: true` で、モデル未指定のまま実行された事実はない。
- **再送はフックの deny が明示的に指示した手順**であり、
  deny 文自身が「エスカレーションの証拠ではない」と宣言している。
  `retry_policy` チェックもこれを再試行回数に数えていない。
- 対して A 周2・周3 は `requested_model: "auto"` かつ
  `launch_rejected: false`、すなわち**リテラル `auto` のままワーカーが
  起動している**。こちらは実行契約違反である。

よって B 周2 は比較条件を満たす。**ただし無料ではない**：
親の往復が1回増えており、費用面では正常系より不利に働く。
モデル省略が正規手順なのではなく、フックに拾わせて直している状態である。
この往復自体をなくすのが次の修正対象。

## 5. cacheW について

本対照で測れるのは**変更による cacheW 量の差**だけである
（A 約 10000〜13000 / B 約 7500〜12000、auto）。
**何が書き込まれたかの特定はできない。** 別の観測根拠が要る。
