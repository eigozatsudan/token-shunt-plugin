# token-shunt

大きなファイルの本文や定型コードの生成結果を、親エージェントのコンテキストに持ち込まないための Claude Code プラグインです。

`PreToolUse` フックがサイズの大きい `Read` と一部の `Bash` 読み取りを拒否し、`bulk-reader` スキルの利用を案内します。スキルは専用サブエージェントに読み取りやコード生成を委譲し、親には短い要約を返します。フックが自動でサブエージェントを起動するわけではありません。

現在のバージョンは **0.1.0（開発中）** です。フック、スキル、専用エージェント、配布用ZIPの作成、ローカル評価・実機比較評価の仕組みを実装しています。**トークン・料金の削減効果は未確認**です。本文のバイト数削減とトークン削減を区別し、リリース可否は比較評価の結果で判断します。**複数ターンの会話では本文の流入を抑えきれない場合があります**（実測。「制限事項」を参照してください）。

設計の背景と受け入れ条件は[設計書](docs/2026-09-12-token-shunt-design.md)を参照してください。

## 動作要件

- Claude Code：`PreToolUse` の入力JSONのトップレベルに `agent_type` を渡す環境が必要です。最低バージョンはマニフェストで固定していません。
- Bash 4以降と `stat`、`head`、`tail`、`awk` などのUnixコマンド。
- `PATH` 上の `jq`。未導入の場合、`SessionStart` で案内し、全 `Read`・全 `Bash`・`Agent` / `Task` のフック対象呼び出しを終了コード2で止めます。読み取り以外の Bash（jq のインストールを含む）も対象です。不正な入力JSONも終了コード2になります。
- 評価には Python 3、実機比較評価・診断には `timeout` と、認証済みで対象モデルを利用できる `claude` が必要です。
- ZIPの作成には `zip` または Python 3、作成後の検証には Python 3 または `zipinfo` が必要です。

## 導入

### 起動時に自動で読み込む

継続利用する場合は、リポジトリを永続的な場所に置き、そのルートから一度だけ実行します。

```bash
claude plugin marketplace add .
claude plugin install token-shunt@token-shunt --scope user
```

以後は通常の `claude` 起動で読み込まれます。起動中の場合は再起動してください。`--scope user` は同じユーザーの全プロジェクトで使う設定です。登録するのは `.claude-plugin/marketplace.json` があるリポジトリのルートで、`plugin/` やZIPの展開先ではありません。[公式のインストール手順](https://code.claude.com/docs/en/discover-plugins)

継続利用の正本は `~/.claude/plugins/cache` にコピーされたプラグインです。リポジトリの `plugin/` を編集しても、このキャッシュは更新されません。更新の合図は `plugin.json` の `version`（現行 0.1.0）です。バンプしたうえで `claude plugin marketplace update` と `claude plugin update token-shunt@token-shunt` を実行するか、再インストールしてください。ローカルマーケットプレイスの自動更新は既定オフです。登録元のリポジトリは更新用に残してください。[配布・キャッシュの仕様](https://code.claude.com/docs/en/plugin-marketplaces)

### 一時的に読み込む

以下はリポジトリのルートから実行します。

```bash
# ソースのプラグインを読み込む
claude --plugin-dir ./plugin

# 配布用ZIPを作成する
scripts/build-zip.sh
```

ZIPの展開方法と構成は[配布用README](docs/distribution/README.md)を参照してください。リポジトリのルートには `.claude-plugin/marketplace.json` もあり、ローカルマーケットプレイスの登録元として使えます。プラグインの参照先は `./plugin` です。

`--plugin-dir` はセッション限定の読み込みで、同名の導入済みプラグインより優先します。指定したディレクトリは、セッション中に削除しないでください。`Read` / `Bash` の実行時にも、その中のフックスクリプトを参照します。参照しているセッションをすべて終了した後なら削除できますが、次回の起動には再配置が必要です。doctor と評価はこの経路を使います。

Spotify の `shunt@portal` とは併用しないでください。他のフックがワーカーの読み取りを拒否すると、本プラグイン側のサイズ制限を通過しても読み取れません。

### Claudeデスクトップで使う

**Codeタブのローカルセッション**はプラグインに対応しています。同じマシン・同じユーザー設定を使うCLIで上記のユーザースコープへのインストールを行った場合は、デスクトップを再起動し、新しいローカルセッションの入力欄で **「＋」→「Plugins」** を開いて `token-shunt` が表示・有効化されているか確認してください。[公式のデスクトップ手順](https://code.claude.com/docs/en/desktop#install-plugins)

Chat / Coworkへの反映はこのCLIインストール手順の対象外です。特にCoworkはCLIの `~/.claude` ではなく、アカウントに同期されるCustomize設定を使います。別PCやコンテナ内のCLIへのインストールも、デスクトップ側には自動で反映されません。[デスクトップの設定と拡張](https://code.claude.com/docs/en/desktop#extend-claude-code)

token-shunt自体のデスクトップ実機検証は未実施です。プラグインの表示に加えて、実行環境でBash・`jq` が利用できることと、フック入力のトップレベルに `agent_type` が渡されることを確認する必要があります。

## 使い方

### 大きなファイルの調査

```text
/token-shunt:bulk-reader --worker-model auto /abs/a.rb /abs/b.rb --question "設定値と定義元を確認"
```

`--worker-model` は `auto`（既定）、`haiku`、`sonnet` を指定できます。未対応の値はワーカーを起動する前に拒否するルールです。

- 1回の委譲で明示的に指定するパスは最大3件です。ワーカーは各領域を1回だけ読みます。`Read` が全文を拒否した場合や、無通知でEOFより前に止まった場合は、実際に返った最終行の次から連続・非重複に継続します。拒否を含む `Read` は全パス合計6回までで、足りなければ `partial` で停止します。関連ファイルの探索や `Grep` / `Glob` は行いません。
- ワーカーの設定は `tools: Read`、`maxTurns: 7`（Read は6回まで、残り1ターンは終了報告用）、`effort: low` です。返答は `confirmed:`、`inferred:`、`unconfirmed:`、`status`、`stop_reason` を含めて最大4,000文字とし、本文や長い引用を返さないルールです。
- `limit=1` の Read も拒否された場合は値の取得を中止し、親子とも `status: partial`、`stop_reason: unreadable_line`、対象パス・未取得行・未確認の値を報告します。取得不能は値の正答と区別し、Grep などで回収しません。
- 親の最終回答にも、各事実の `confirmed:` と絶対パスを同じ項目に保持します。
- ファイル間の関係を調べる場合は、関係するパスを同じ委譲に含めます。4件以上は最大3件ずつに分け、根拠を照合できる事実だけを統合します。不明な関係を推測で確定しません。
- 境界ファイルの追加確認は質問ごとに最大1回です。再試行を含む委譲の合計上限は後述の4回です。開始前に上限を超えると分かる場合は、対象を絞ります。
- 追加質問は同じパスを渡した新しい呼び出しで処理します。回答の再利用索引や `resume` は使わず、再読み取りも使用量に含めます。

### 定型コードの生成

```text
/token-shunt:code-writer --worker-model haiku --reference /abs/greeter.py --target /abs/greeter_test.py --verify "python3 -m unittest discover -s /abs -p greeter_test.py" --spec "参照に沿ったテストを生成"
```

参照ファイルから大部分を予測できるテスト、設定、型スタブなどが対象です。新しいロジックの設計、デバッグ、安全性が重要なコードの生成には使いません。

- ワーカーの設定は `tools: Read, Write, Grep, Glob`、`maxTurns: 12`、`effort: low` です。書き込み先は指定したターゲットに限定し、既存ファイルは先に読みます。内容確認は最大16ファイル、`Read` / `Grep` / `Glob` の合計20回までです。
- 返答は出力パス、行数、3〜5項目の要約、`status`、`stop_reason` を含めて最大800文字とし、生成コードを載せません。
- 親が検証コマンドを実行します。検証コマンドが未指定の場合は拡張子に応じた構文確認または最小限の確認を使います。
- `verification: minimal` は空ファイルなどの粗い不備の確認、`syntax` は構文確認です。どちらも内容の正しさは未確認なので、結果は `partial` として残りの確認事項を報告します。受け入れ条件を確認できた場合のみ `requirements` として完了を報告します。
- 同じターゲットへの書き込みは直列で行います。親の `Write` を止めるフックはありません。

### 小さい作業とモデル選択

小仕事の経路、モデル切り替え理由、総起動数はスキル・エージェントへの指示です。`check-agent-model` は token-shunt の reader / writer の起動時に `model=haiku|sonnet` の明示指定を要求し、省略・`auto`・その他の値を拒否します。拒否された起動は同じモデル方針で指定を直して再送します。

- 指定ファイルまたは必要と分かっている範囲の合計が **16,384バイト以下**で、それぞれの `Read` がフックを通過する場合、親が直接読みます。大きなファイルでも、既知の短い範囲なら範囲指定の `Read` を使います。
- 必要量が16KiBを超える場合は、フックのしきい値以下でもスキルが委譲を判断します。ファイル数だけでは判断しません。サイズの確認に本文を読み込まず、メタデータを使います。
- 生成結果が50行未満、参照の合計が16KiB以下、必要な `Read` がすべて通る場合は、親が生成・検証します。
- `auto` は Haiku で開始し、必要な根拠の不足、返答ルール違反、生成後の検証失敗がある場合に限り、最大1回 Sonnet へ切り替えます。権限・認証エラー、未指定の依存先、読み取りや予算の制限では切り替えません。
- 1つの質問での委譲は、両ワーカー、バッチ、境界確認、再試行を合わせて **最大4回**です。

## フックの動作

### Read：`check-file-size`

ファイル全体が行数・バイト数のどちらかのしきい値を超える場合、通常の読み取りを拒否します。既定値は **350行、65,536バイト**で、ちょうどしきい値の値は超過に含めません。

`limit` を指定した読み取りは、実際の対象範囲が両しきい値と走査予算に収まれば通過できます。`offset` の省略時は1行目からです。`offset` だけでは範囲指定の例外になりません。1行だけでもバイト数のしきい値を超えれば拒否します。

シンボリックリンクはリンク先のサイズで判定します。通常ファイル以外と、実装で列挙した画像拡張子、`.pdf`、`.ipynb` はサイズ判定の対象外です。

ファイル名に含まれる末尾の改行も保持し、指定されたパスそのものを検査します。Read / Bash / Grep とも、入力JSONに絶対パスのトップレベル `cwd` があれば相対パスの基準に使い、省略時はフックの起動ディレクトリを使います。

### Bash：`check-bash-read`

シェル全体を解釈するのではなく、対応するコマンドと明示的な入力ファイルを検査します。解析中も3秒の経過時間予算を定期確認し、超過時は拒否します（個々の停止したファイルシステム呼び出しは中断できません）。解析時間を抑えるため、コマンドが8,192バイトを超える場合は解析前に拒否します。

| コマンドの形 | 判定 |
|---|---|
| 単独の `cat` / `less` / `more` | 入力ファイル全体をしきい値で判定 |
| 単独の `head` / `tail` | 解釈できる行数指定は実際の範囲、バイト数指定は出力予定バイト数を判定。引数なしは10行、行数0は空出力として通過。不明なオプションはファイル全体で判定 |
| パイプ末尾の `head` / `tail` | 純粋な標準入力を読む、解釈可能な `-c N` で `N` がバイトしきい値以下の場合に通過 |
| パイプ末尾の `cat` / `tee` / `less` / `more`、未対応・解釈不能な末尾 | 各段の対応する読み取りコマンドの明示的入力を検査。`head` / `tail` 自身の範囲指定も判定に使う。`tee` の引数は出力先として扱う |
| `;` / `&&` / `||` / 改行 / `&` でつないだ複合コマンド | 各区間の対応する読み取りコマンドの明示的入力をファイル全体で判定 |
| 単独コマンドの `>` / `>>` | すべての標準出力の転送先が通常ファイル（新規を含む）または `/dev/null` なら、入力ファイルの判定を省略 |

引用符とエスケープ内の `|` や `#` を文字として扱い、シェルコメントを行末まで除外します。標準出力・標準エラーへ戻るリダイレクト先、その他の特殊ファイル、未解決の展開は、判定省略の対象になりません。リンク先はファイルの同一性と、利用可能なら `readlink -f` による正規化パスで確認します。

引用・エスケープされた `>` などはファイル名の文字として扱います。実際のリダイレクト演算子と区別し、後続の入力ファイルも検査します。

`01>` のように先頭ゼロを含む標準出力のファイル記述子も `1>` と同じように判定します。

`2>errors cat large` のようにリダイレクトを前置しても、明示的な入力ファイルを検査します。heredoc本文はコマンドとして扱いません。名前付きfd（`{fd}>...`）、ANSI-C／ロケール引用のheredoc区切り、非引用heredoc本文のバックスラッシュ改行と有効なコマンド置換（`$(...)`・バッククォート）は、安全に解釈できないため拒否します。引用した区切りの本文はリテラルとして扱います。`<<$D` の区切りは Bash と同じく文字列 `$D` であり、変数展開しません。`<<$(...)` やバッククォートを含む非引用区切りは、区切り語の字句解析に対応していないため本文をマスクする前に拒否します。必要なら区切り全体を単一引用符で囲んでください。

先頭のリテラルな `cd <dir>` / `cd -- <dir>` が `&&`、`;`、改行で続く場合は、移動先を基準に後続のファイル引数を解決します。

### Grep：`check-grep-bounds`

本文を返す `Grep`（`output_mode: content`）が、**小仕事の予算 16,384バイトを超える1ファイル**を対象にする場合だけ判定します。§26.5 の2規則をこの1本で扱います。

1. **メタデータが先。** そのファイルのサイズをまだ確認していない場合は拒否し、`wc -c <path>` を先に実行するよう返します。サイズは `PostToolUse` の Bash（引数が展開もコメントも含まない `wc -c` / `stat`。`stat` は書式を指定するならサイズ `%s` を含むものに限り、`-f` は対象外）と、`check-file-size` の拒否本文が実際にサイズを告げたパスから記録します。成功した `Read` は記録しません（本文を受け取ることはメタデータで判断したことになりません）。
2. **出力に上限。** 確認済みでも、`head_limit` が1〜20の整数でなければ拒否します。`-A` / `-B` / `-C` / `context` の併用も拒否します（前後行は上限を実質的に無効にするため）。

`output_mode` が `files_with_matches`（既定）や `count` の場合、対象がディレクトリ・`glob` 併用・複数ファイル・存在しないパスの場合、およびファイルが予算以下の場合は、いずれも判定しません。

相対パスは、`Read` / `Bash` と同じく入力JSONのトップレベル `cwd`（絶対パスのみ）を基準に解決します。`cwd` が無ければフックの起動ディレクトリです。不正な `cwd` は拒否します。ただしサイズを記録する経路（`PostToolUse` の Bash と `check-file-size` からの通知）では拒否に意味が無いため、絶対パスのオペランドだけを記録します。

記録はセッションとエージェントの単位で、ファイルの inode・サイズ・更新時刻がすべて一致するときだけ「確認済み」とみなします。ファイルが変われば再確認が必要です。状態が失われた場合（新しいセッション、コンパクト後など）は未確認として扱います。ここで通してしまうと規則が黙って失効するためで、代償は `wc -c` の1往復です。

同じセッション・エージェントでの拒否が **6回**に達すると、以後は再試行を促さず、終了指示を返します。拒否の往復だけでトークンを使い切らせないためです。

**`token-shunt:code-writer` への案内だけは別です。** writer のツールは Read / Write / Grep / Glob で Bash が無く、`check-file-size` は writer の Read をサイズ免除するため、**writer にはサイズを知る手段がありません**（成功した Read は記録しないため）。したがって予算超過ファイルへの content Grep は writer では常に拒否されます。この場合の本文は `wc -c` も `bulk-reader` への委譲も勧めません（どちらも writer が持たない経路です）。代わりに `files_with_matches` か必要範囲の `Read` を案内し、確認できなかった点を添えて報告するよう返します。親側の案内（`wc -c`、および上限到達時の「部分的な結果で報告するか `bulk-reader` に委譲」）は従来どおりです。判定に使うのは実行環境がトップレベルに設定した `agent_type` だけで、モデルが書ける `tool_input.agent_type` は使いません。

### 通過時とワーカーの扱い

通過時は `permissionDecision` を出力せず、通常の権限確認や他のフックの判定を維持します。サイズ超過などによる拒否時は `permissionDecision: deny` と理由を返します。

実行環境が入力JSONのトップレベルに設定した `agent_type` が完全一致する場合だけ、次のサイズ判定を免除します。

| `agent_type` | Read | Bash |
|---|---|---|
| `token-shunt:bulk-reader` | 免除 | 免除（現在のエージェント定義ではBashを付与していません） |
| `token-shunt:code-writer` | 免除 | 免除なし |

モデルが指定できる `tool_input.agent_type` は使いません。免除対象でも `jq` と有効な入力JSONは必要です。

**このフックが強制する範囲**: 1回の委譲で扱うパスは最大3件、最初の Read は必ず `offset=1`（後の領域だけが必要な場合も同じ。以降は実際に返った行の次から連続）、`limit` は正の整数、同時Readの禁止、拒否を含めて合計6回まで。これらは指示ではなく拒否で担保します。bulk-reader の契約状態は同じセッション・エージェントで維持します。Read の完了通知が300秒届かない場合は、その委譲を終了扱いにし、`partial` で停止させます。読み取りの再開や予算のリセットは行いません。状態ロックの取得待ちは250ミリ秒までで、取得できなければフックを失敗させます。

### Stop / SubagentStop：`check-final-answer`

**既定で有効**です。親の回答が終わるたび（`Stop`）と、reader ワーカーが終わるたび（`SubagentStop`）に起動し、ワーカーが出した `confirmed:` 行が最終回答に保持されているかを見ます。保持されていなければ `decision: block` と直し方を返し、CLI にもう一度書かせます。

`TOKEN_SHUNT_SENDBACK` に `off` / `0` / `false` / `no` のいずれかを設定すると無効になります。無効時はセッションファイルを読まず、プロセス起動1回分だけの費用です。

**判定できるときにだけ差し戻します。** 次のいずれかに当たれば、そのまま通します。

| 通す場合 | 理由 |
|---|---|
| `stop_hook_active` が真 | 再ブロックの抑止。CLI の上限到達とは別 |
| ワーカーがまだ実行中 | 判定する回答がまだ無い。行は転送中 |
| ワーカーの出力が**1件も**取得できない／最終回答を特定できない | 突き合わせる対象が無い。取得できたワーカーが1件でもあれば、取得できなかった分だけを除外して判定します |
| ワーカー側の報告が契約の形でない | 親の落ち度ではない（reader ワーカーには `SubagentStop` 側で別途差し戻す） |
| 保持の判定が `undetermined` | 引用先が現存しないなど。判定不能を違反として扱わない |
| 最終回答がセッションファイル由来 | 停止しようとしている本文はまだ書かれていない。古い本文で違反を作らない |

`SubagentStop` 側の対象は `token-shunt:bulk-reader` だけです。writer も、利用者が委譲した任意のエージェントも、読み取り契約の下にはありません。事実を持っているのに契約の形で書いていない報告（`confirmed:` 行が無い、絶対パスを伴わない）だけを差し戻し、`unconfirmed:` だけの正しい報告や、ターンが成立しなかった報告は通します。

**bulk-reader を使っていないセッションでも毎ターン末に起動し、セッションファイルを読みます。** 読み込み量の上限は `TOKEN_SHUNT_SESSION_MAX_BYTES`（既定 64 MiB）で、これを超えるセッションでは何もしません。判断の経緯は `reviews/sendback-registration-decision-2026-09-15.md` にあります。

なお **実機比較評価は既定でこれを切ります**（`evals/compare/run.sh` が `TOKEN_SHUNT_SENDBACK=${SENDBACK:-off}` を設定するため）。製品の既定とは逆なので、評価で有効にするには `SENDBACK=on` を渡します。

## 環境変数

| 変数 | 既定値 | 用途 |
|---|---|---|
| `TOKEN_SHUNT_MIN_LINES` | `350` | 読み取りの行数しきい値 |
| `TOKEN_SHUNT_MIN_BYTES` | `65536` | 読み取りのバイト数しきい値 |
| `TOKEN_SHUNT_SCAN_BUDGET_BYTES` | `8388608` | 走査のバイト予算。`offset` までの読み飛ばしも含む |
| `TOKEN_SHUNT_SCAN_BUDGET_MS` | `2000` | 走査後に確認する経過時間の上限（ミリ秒） |
| `TOKEN_SHUNT_HOOK_LOG` | 未設定 | 評価補助用。フック名・判定・理由・帰属情報を1行のJSONで追記。2026-09-19以降、`record-coverage`がRead 1回ごとの被覆行（開始行・行数・ファイル総行数・バイト数）も同じファイルに追記する。**判定には一切影響しない** |
| `TOKEN_SHUNT_SENDBACK` | 未設定（有効） | `off` / `0` / `false` / `no` で `check-final-answer` の差し戻しを無効化 |
| `TOKEN_SHUNT_SESSION_BUDGET_BYTES` | 未設定（無効） | 会話累積の取り込み予算。設定すると、そのセッションで親が取り込んだ本文バイトの合計が値を超えた後の全文 `Read`（と既知 reader の `Bash`）を拒否する。**既定では何もしません。効果は実機未検証です** |
| `TOKEN_SHUNT_SESSION_MAX_BYTES` | `67108864` | 差し戻し判定が読むセッションファイルの上限。超過時は何もしない |
| `SENDBACK_TRIAL_LOG` | 未設定 | 評価補助用。差し戻しの判定記録を1起動につき1件のJSONで追記 |
| `TOKEN_SHUNT_CASE_TIMEOUT` | `600` | 実機比較評価での各CLI呼び出しの制限時間（秒） |
| `SUITE` | 未設定 | 実機比較評価の対象スイートを絞る。例：`A` |

4つのしきい値・走査予算は非負整数を受け付け、負数や不正な値は既定値に戻します。

環境変数、`PATH` 上の実行ファイル、`BASH_ENV`、CLI設定、同一ユーザーの一時状態領域は信頼する実行環境です。これらを変更できる主体に対するサンドボックスではありません。しきい値の変更や状態削除を含め、同一ユーザーによる設定・状態操作を強制的に防ぐ仕組みはありません。

`TOKEN_SHUNT_HOOK_LOG` はパスや Bash コマンド全文も記録するため、保存先の閲覧権限を管理してください。Python 3を使う任意の補助機能として、通常ファイルにのみ追記します。シンボリックリンク、FIFO、ファイル記述子を指す特殊な保存先などはスキップし、標準出力へログJSONを混入させません。

巨大な1行を丸ごと行解析器へ渡さないように、前方走査は予算に先読み1バイトを加えた範囲に入力を制限します。末尾走査も同じ大きさの末尾部分に制限し、別途1バイトで改行を確認します。前方走査の解析器には固定の終端マーカー1バイトを加え、最終行の改行有無を stat サイズに依存せず判定します。このマーカーはファイル読み取り量には含めません。必要な範囲を走査しきれない場合は拒否します。これは解析器への入力上限であり、OSやコマンド内部の先読みまでは制限しません。

時間は走査後に確認するため、停止したファイルシステムの読み取りを中断する仕組みではありません。`Read` / `Bash` フックのタイムアウト設定は10秒で、走査予算を絶対的な遮断保証とは扱えません。

### 依存不足からの復旧・無効化

jq、Bash 4以降、Python 3の導入は、Claude の Bash ツールではなく通常の外部ターミナルで行ってください。導入後、同じ PATH で Claude を再起動します。古い Bash は Read / Bash フックで終了コード2により拒否し、doctor も失敗として報告します。Python 3がない場合は `check-file-size` が bulk-reader の Read を終了コード2で遮断し、契約フックの起動失敗だけで読み取りが通過することを防ぎます。契約フック自体は全 Read の Pre / Post / Failure イベントに登録されているため、Python 3がなければ非ワーカーでも起動に失敗します。その場合の非ワーカーへの影響は、CLIの起動失敗の扱いに依存し、実機では未確認です。`check-grep-bounds` と `check-final-answer` も同じく Python 3 の shebang で動くため、Python 3 がなければ同様に起動しません。起動失敗の扱いはいずれも CLI 依存で実機未確認ですが、**規則が適用されないこと自体は確実**です（フックが遮断を返す機会が無いため、Grep の上限と差し戻しは効かないものとして扱ってください）。SessionStart の警告はこの3件をまとめて告げます。

ユーザースコープの導入を一時停止する場合も、外部ターミナルで次を実行してから Claude を再起動します。

```bash
claude plugin disable token-shunt@token-shunt --scope user
```

再開は `claude plugin enable token-shunt@token-shunt --scope user`、削除は `claude plugin uninstall token-shunt@token-shunt --scope user` です。project / local に導入した場合は同じ scope を指定します。`--plugin-dir` だけで読み込んでいる場合は、その引数を外して起動します。管理者配布は管理者に変更を依頼してください。[公式の管理コマンド](https://code.claude.com/docs/en/plugins-reference#cli-commands-reference)

## 制限事項

- `@file` は Read ツールを通らないため制限しません。`Grep` の本文出力は `check-grep-bounds` が扱いますが、単一ファイルを対象にした場合だけです。ディレクトリ全体の本文検索は制限しません。コマンド置換の結果表示（`echo $(cat large.txt)`）、`git show` / `jq` / `journalctl` のように本体が未対応のコマンドが出す本文も検査しません。未対応の末尾を持つパイプでも対応 reader の各段は検査しますが、未対応コマンド自身の読み取りは検査しません。
- 引用外のプロセス置換 `<(…)` / `>(…)` は、内部の読み取りと出力先を安全に解釈できないため拒否します。対象 reader の未解決の glob・チルダ・brace 展開は、出力のバイト上限や通常ファイルへの隔離が確認できる場合を除いて拒否します。先頭の `cd` を追跡できなくなった後の対象 reader も拒否します。必要なファイルを引用した明示パスで指定してください。
- 先頭トークンを変えるグループ化・制御構文（`(cat file)`、`{ cat file; }`、`if ...; then cat file; fi`、`while ...; do ...; done <file`）と、`!`、`time`、`timeout`、`command`、`env`、`nice`、`ionice`、`sudo`、`stdbuf`、`exec`、`busybox` を前置した呼び出しは、前置語を取り除いて実際のコマンドを判定します（2026-09-16）。前置語自身のオプションで解釈できないものが現れた時点で除去を止めるため、未知のオプションを伴う前置は従来どおり素通りします。`for f in ...; do cat $f; done` のように本文パスが展開になる場合は、未解決の展開として拒否します。
- 入力リダイレクト `<` は、ファイルオペランドと同じ扱いで検査します（2026-09-16）。`cat <large.txt`、`nl <large.txt`、`xargs echo <large.txt`、ループの `done <large.txt` を拒否し、`head -c 100 <large.txt` と `wc -c <large.txt` は通します。`<<`・`<<<`・`<&`・`<>` は対象外です。`dd if=` は、`of=` が無く `bs`×`count` がしきい値以下でもない場合に拒否します。
- `cat` 以外の全文 reader（`nl`、`od`、`xxd`、`base64`、`strings`、`rev`、`tac`、`fold`、`expand`、`unexpand`、`pr`、`shuf`、`cut`、`paste`、`column`、`diff`、`sdiff`、`comm`）も `cat` と同じしきい値で判定します（2026-09-16）。`od -N` や `xxd -l` のような出力側の上限は解釈しないため、大きなファイルでは拒否します。`grep` / `egrep` / `fgrep` / `rg` は、`-l` / `-L` / `-c` / `-q`（および長形式）があるか、20 行までの上限（`-m N` またはパイプ末尾の `head -n N`）がある場合に通します。20 行は Grep ツール側の `head_limit` と同じ上限で、前後行の窓がある場合と、ファイルオペランドが 2 つ以上の場合（`-m` はファイルごとの上限のため）は認めません。`cat large.txt | head -n 20` は従来どおり拒否します（grep の出力は一致行だけですが、全文 reader の出力はそうではありません）。
- `sed`、`awk`、`perl`、`python`、`ruby`、`node`、`php`、`pwsh`、`bash -c` などのインタプリタは、呼び出し文字列（`-c` / `-e` の中を含む）に現れる実在パスをすべてしきい値で判定します（2026-09-16）。`sed -i` は通し、`python3 big.py` の script オペランドは判定対象外です。`bash -c` / `sh -c` などシェルの `-c` プログラムは、パスの走査ではなく同じフックに再入して判定します（`bash -c 'wc -l large.txt'` は通り、`bash -c 'cat large.txt'` は拒否します。入れ子は 3 段まで）。プログラムが組み立てるパスや変数経由のパスは検出できません。`xargs -a file` / `xargs cmd <file` と、`find ... -exec` の後ろに全文 reader や上限なしの `grep` が来る呼び出しも拒否します。`find -exec` は一致するファイルのサイズが分からないため、サイズによらず拒否します（`-exec python3 -c ...` のようなインタプリタ経由は対象外です）。
- コマンド名や対応 reader のファイル引数にある、引用外・二重引用内の有効な `$` 展開は未解決として扱います。ANSI-C引用・ロケール引用も含み、既存の出力隔離・バイト制限の例外を除いて拒否します。単一引用内やエスケープされた `$` はファイル名の文字として扱います。
- Bashのディレクトリ追跡は先頭の限定的な `cd` 連鎖のみです。条件分岐、バックグラウンド実行、グループ化、展開、`--` 以外の `cd` オプション、他のコマンドの後の `cd`、`CDPATH` に依存する相対移動などでは絶対パスを使ってください。
- 拡張子による画像・PDF・notebook の免除は内容の真正性を検証しません。拡張子変更後にフックが通過しても、実際の Read がその内容を受理・出力するかは別であり未検証です。`NotebookRead` 用のフックは登録していません。
- Explore / Plan / general-purpose の起動自体は止めません。これらの大きな `Read` はサイズ判定の対象です。
- 出力が小さくても、フックが上限を読み取れないコマンドは拒否します。実測の代表例: `awk -F, '{s+=NF} END{print s}' big.csv`（数値1行）、`sed -n '1,5p' big.csv`（5行）、`cut -d, -f1 big.csv | sort -u | head -5`（5行）、`grep -n xyz big.csv`（不一致で0行。`-m 20` を足せば通ります）、`diff big.csv big2.csv`（差分のみ）、`find . -name '*.csv' -exec grep -n xyz {} +`（0行）。`wc` / `stat` でサイズを確認してから範囲指定の `Read` を使うか、委譲してください。
- 判定はファイル単位で、同一呼び出しの複数オペランドも合計しません。呼び出しをまたぐ読み取り量も集計しません。小さな範囲の反復による全文読み取りをフック単体では防げません。スキルでは禁止しています。比較評価が委譲経路の違反として判定するのは**会話の最初のターンだけ**です（判定器は1ケースにつき1つのtranscriptを読みます）。
- **複数ターンの会話では、親がファイル本文を取り込む場合があります（実測、2026-09-19）。** 1ターンにつきしきい値以下のファイルを1つずつ要求される場合、個々の`Read`は常にしきい値以下なのでフックは掛からず、小仕事の16,384バイト予算はターンごとの判断なので会話をまたいで累積しません。5ターン会話14本の実測では、**最初のターンでの取り込みは0件**、**2ターン目以降で21件、14本中10本**で発生しました。最も多い1本は3ターンで計**32,098バイト**を親が取り込み、**プラグインを使わない場合の最小値（25,901バイト）を上回りました**。ワーカーが既に読んだファイルへの再`Read`は5件中5件とも拒否されており、**取りこぼすのは後続ターンが新しく要求するしきい値以下のファイルだけ**です。累積量を機械的に強制する仕組み（Lock B）は同梱していますが、**既定では無効**です。`TOKEN_SHUNT_SESSION_BUDGET_BYTES` に上限バイト数を設定した場合にだけ、超過後の全文`Read`を拒否します。**この機構の効果は実機で検証していません。**既定のままなら、動作はこの節に書いたとおり（累積は強制されない）です。会話全体を数える計器は`evals/compare/parent_turn_reads.py`です。詳細は[設計書](docs/2026-09-12-token-shunt-design.md)の26.2を参照してください。
- 編集には、親が場所を確認し、元ファイルの対象範囲を `Read` で正常に読めることが必要です。子の行番号だけでは編集せず、`head` / `tail` の閲覧結果、バイト範囲の抜き出し、一時ファイルを使った代替も編集の根拠にしません。
- 子の最終返答を機械的に切り詰めたり、コードブロックを除去したりする処理はありません。文字数や引用の制約はエージェントへの指示です。
- 比較評価の判定器は、CLI 2.1.x の `hook_response` からフックのコマンド名を特定できません（`hook_name` はマッチャ名のみ）。他プラグインのフック混入は、隔離条件と「`token-shunt` を名乗らない拒否理由」で検出します。同じマッチャに載った外来の**通過**フックは出力が空なため区別できません。
- 1つの巨大ファイルを行数で均等分割しません。関連ファイル探索や回答の再利用もv0.1の対象外です。
- 親入力トークン、子の使用量、親子合計の推定USDは別々に評価します。月額料金や一定割合の料金削減は保証しません。

## 評価と診断

```bash
# フック（reader契約を含む）、診断の回帰、ZIP構成・実行権限、マーケットプレイスの検証
# Claude CLIなしでも実行可能。CLIがあれば plugin validate も実行
evals/run.sh

# 比較評価のオフライン回帰チェック
python3 -m unittest discover -s evals/compare -p 'test_*.py'

# 実機比較評価：認証済みのClaude CLIが必要
evals/compare/run.sh
evals/compare/run.sh <case-id>
SUITE=A evals/compare/run.sh

# ソースツリーの診断（--plugin-dir の隔離プローブ。実機呼び出しを含む）
scripts/doctor.sh
```

比較評価は [cases.json](evals/compare/cases.json) に指定されたモードを実行します。プラグインなしの `direct` と、プラグインを読み込む `haiku` / `sonnet` / `auto` のうち、各ケースで定義された組み合わせを比較します。各ケースを必ず2回だけ実行する仕組みではありません。

ネイティブ Read の上限は全モード共通で25,000トークンに固定します。約70KBの単一行を比較する `compare-one-line` / `auto-one-line` だけは、Read可能なベースラインを確保するため40,000に設定します（`CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS`）。カタログの `read_max_output_tokens` と解決済み実行仕様に記録し、フックのサイズ制限は変更しません。この2ケースはCLI標準上限での可読性試験ではありません。

CLI設定の分離には `--setting-sources ""` とクリーンな作業ディレクトリを使います。フック評価と実機CLIへは ambient の `TOKEN_SHUNT_*` と `CDPATH` を渡さず、カタログで指定した環境値またはランナーが生成した fixture パスだけを明示設定します。認証・PATH・モデル上書きの診断に必要な変数は保持します。`TOKEN_SHUNT_CASE_TIMEOUT` は引き続きランナー側の制限時間を設定します。`claude` がなければスキップしますが、プラグインの読み込み失敗、`direct` への本プラグインの混入、他のフックの混入は失敗として扱います。

事前プローブではCLIの終了コードと初期化・最終結果も確認します。利用上限や認証エラー、結果の欠落などで正常に完了しなかった場合は、評価本体を開始せず失敗を報告します。

ケース本体のCLI終了コードは各判定の `cli_exit_code` に保存します。非0終了だけでは不合格にせず、トランスクリプトの正答・経路・隔離と必要なディスク検証で合否を決めます。結果イベントの欠落やエラー結果は不合格です。事前プローブの非0終了は引き続き環境失敗として扱います。

各実行の計画、判定、トランスクリプトは `evals/compare/tmp/runs/run.*` に保存し、各モードの前にモデルが参照する入力と出力先を初期化します。証跡はその初期化対象の外に残します。集計結果は `evals/compare/last-run.json` です。開始時に旧結果を無効化し、完了した JSON だけを公開します。中断時の過去の成功結果を現在の結果として使いません。ケースのタイムアウト後は10秒の猶予で強制終了します。

末尾の `done:` と失敗理由は、ディスク検証・隔離判定を反映した最終集計から表示します。事前プローブの件数は `probes:` に分け、実行数には含めません。集計全体のエラーも実行失敗数に加算せず `ERROR` として表示します。

`selected_run_valid` は選択したケース・スイートの実行結果、`release_eligible` はリリース評価としての可否を示します。一部のケースの成功だけではリリース検証完了になりません。全文混入の判定はUTF-8バイト数で行い、必須の親入力トークン内訳・親出力トークン、子の使用量、合計推定費用とは区別します。

reader の子返答には `status: complete|partial` と空でない `stop_reason:` を必須とし、欠落を判定器で失敗にします。壊れた JSONL 行や不正なツール入力型も、理由を付けて失敗にします。`require_parent_tokens` は真偽値または対象モードの配列を受け付け、単体判定と集計で同じ意味に扱います。宣言された `gold_file` が欠落・不正・空ならモデル呼び出し前に失敗とし、正答検査を省略しません。試行ごとの要求モデル・終了状態・理由を `worker_attempts` に保存し、観測できない値は null にします。model フックで起動前に拒否された呼び出しは、拒否証跡があり子の活動がない場合だけ実起動から除外し、試行記録には残します。

`suite_cost_usd` は大容量4ケースの今回の CLI 報告費用を集計します。欠測を0にせず、失敗実行の費用も除外せず合否を併記します。単回の合計であり、設計の48実行・3反復中央値による費用回帰実験の代替ではありません。費用だけでは出荷合否を変えません。

親に追加された内容量には、Agentのプロンプト、Writeの本文、Bashのコマンドなど、親が出したツール引数も含めます。引用検査は開始位置によらずUTF-8で2,048バイトを超える連続引用、または実際に連続した21行以上の引用を検出します。

本文量はツール呼出ID・イベントUUIDで再送を除外し、同じAPI応答内でも別の内容ブロックは計上します。親の使用量は各ターンの `result.usage` を合算し、必要な区分が欠測なら0で補わず未検証とします。引用検査に必要なfixtureが一つでも読めない場合も合格にしません。

`scripts/doctor.sh` はソースツリーのプローブです。`--plugin-dir "$ROOT/plugin"` と `--setting-sources ""` で隔離ロードし、ユーザースコープのキャッシュは見ません。`jq`、CLIバージョン、プラグインとエージェントの登録、Haiku / Sonnet の指定モデルと実際のモデル、観測可能な `effort` や終了状態を確認します。`plugin + agent registration: confirmed` はソース側の登録確認であり、導入済みコピーの有無・新旧・フック実行ビットの確認ではありません。`CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` の場合はモデル比較を無効として報告します。認証などにより実機確認できない項目は `unconfirmed` とし、診断項目のうち `jq` 不足を失敗として扱います。終了コード0だけで全項目の確認済みとは判断しないでください。

プラグインと両エージェントの登録を確認できると、CLIバージョンなどを [doctor-last-probe.txt](docs/distribution/doctor-last-probe.txt) に記録します。これは診断の記録であり、最低バージョンや全機能の動作保証ではありません。フック入力のトップレベル `agent_type` は別途実際の入力で確認する必要があります。`TOKEN_SHUNT_HOOK_LOG` は判定・理由と、帰属用の session_id / tool_use_id・対象パスまたはコマンドを保存します。2026-09-19以降、`record-coverage`がRead 1回ごとの開始行・行数・ファイル総行数・バイト数も保存します。**メタデータは保存しますが、Read本文（入力JSON全体やファイルの中身）は保存しません。**コマンド文字列が残るためログは診断用として管理してください。

Bulk-reader の Read 契約は Python 3（Unix の `fcntl` が必要）のフックで強制します。起動ごとに6試行、同時Readの拒否、実返却行によるカーソル更新、拒否後の切り捨て半減を管理します。状態はユーザー専用の一時ディレクトリにメタデータだけを保存します。識別子・返却範囲が確認できない場合は継続を拒否します。`maxTurns` はRead回数の保証ではありません。

### 2026-09-14 レビュー修正後の境界

- Bash の `+=` 代入を認識し、引用・エスケープされていないコマンド名の brace / glob / tilde 展開は拒否する。引用済みリテラル名は展開扱いにしない。
- 同一 Bash 呼び出し内の先行コマンドやパイプの別ステージがファイルを変更し得る場合、対象 reader の事前サイズ検査を信用しない。準備と読取を別々の Bash 呼び出しに分ける。解決可能な先頭 `cd` と明示バイト制限を持つ隔離済み出力は引き続き利用できる。別プロセスによる検査後の変更まで防ぐ OS レベルのファイル固定ではない。
- reader のパス状態は実パスに正規化して管理し、通常例外は exit 2 で閉じる。
- 子の返答上限・status・本文検査と要求/解決モデルの照合は reader / writer ともケース宣言に依存せず適用する。本文照合は fixture に加え観測した子ツール結果（Read / Grep / Bash 等）と Write 内容を使い、親の thinking も親コンテキスト量と本文照合に含める。非公開・非出力の thinking は transcript から検査できない。
- `SessionStart:startup` は空の正常応答のみ既知 bootstrap と互換扱いする。同名でも非空の出力・stderr・失敗は外来フックとして拒否する。空の正常応答だけの外来 startup フックは CLI の出力から識別できず、この制限は同名 PreToolUse pass と同様に残る。
- 費用は CLI 報告値。`repeat.sh` は全カタログの固定順反復（既定2回）で、48実行・順序交替・単価再計算は将来計画。設計 §26.5 に実装との差を明記する。
